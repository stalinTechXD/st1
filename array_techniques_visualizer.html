🧮 Array Precomputation (Prefix Sums) precompute once

Precompute cumulative information so repeated queries become O(1). The prefix-sum array lets any range sum be a single subtraction.

💡 Intuition

Do the work upfront: build prefix[i] = a[0]+…+a[i] in one pass. Then sum(l, r) = prefix[r] − prefix[l−1] in O(1), no matter how many queries. Array [3,1,4,1,5,9] → range [1,4] sum = 11.
build prefix[] once→range sum = prefix[r]−prefix[l−1]→O(1) per query

📐 Maximize the Expression |a[i]−a[j]|+|i−j|

Maximize |a[i] − a[j]| + |i − j| over all pairs. Splitting the absolute values turns an O(n²) scan into two O(n) precomputations.

💡 Intuition

Unfold the absolutes: the expression equals max of (a[i]+i) − (a[j]+j) and (a[i]−i) − (a[j]−j). So build a[i]+i and a[i]−i, and each answer is just max − min of that array. Array [3,1,5,2] → 5.
P = a[i]+i, M = a[i]−i→max−min of each→answer = the larger
🔒 Keep forever: "Break |a[i]−a[j]|+|i−j| into (a[i]±i); the answer is max(maxP−minP, maxM−minM)."

📊 Largest Rectangle in Histogram monotonic stack

Find the biggest rectangle fitting under a histogram. A stack of increasing bars lets each bar's max width be found in one pass.

💡 Intuition

Pop when a shorter bar arrives: keep a stack of indices with increasing heights. When a bar is shorter than the stack top, that top can't extend further right — pop it and compute its rectangle (height × width). The widest span uses the new left boundary. Heights [2,1,5,6,2,3] → 10.
push increasing bars→shorter bar? pop & measure→track max area
🔒 Keep forever: "Histogram rectangle = monotonic stack; on each pop, area = height × (right − left − 1)."

🧩 Maximum Chunks to Make Sorted prefix max = index

Split the array into the most chunks so that sorting each chunk and concatenating yields the fully sorted array.

💡 Intuition

Cut where the max catches up: scan left to right tracking the running max. You can end a chunk at index i exactly when max(a[0..i]) == i (everything so far belongs before this point). Count those cut points. Array [1,0,2,3,4] → 4 chunks.
track running max→max == index? cut here→count cuts

🔄 Rotate the Array reversal trick

Rotate right by k in O(1) extra space using three reversals — no temp array needed.

💡 Intuition

Reverse, reverse, reverse: to rotate right by k: reverse the whole array, then reverse the first k, then reverse the remaining n−k. The double-flip lands every element in its rotated spot. [1..7] rotate by 3 → [5,6,7,1,2,3,4].
reverse all→reverse first k→reverse rest
🔒 Keep forever: "Rotate by k = reverse whole, reverse first k, reverse last n−k. O(1) space."

🐢 🐇
🧠
Never forget: always take k = k % n first — rotating by n (or more) is the same as rotating by the remainder.

🪟 Sliding Window Technique reuse the overlap

For fixed-size window problems, slide instead of recomputing: add the entering element and remove the leaving one — O(n) overall.

💡 Intuition

Don't re-sum every window: compute the first window's sum, then for each step add a[right] and subtract a[left]. Track the best. Max sum of a size-3 window in [2,1,5,1,3,2] → 9 (5+1+3).
sum first window→slide: +a[right] −a[left]→track max
🔒 Keep forever: "Sliding window reuses overlap: add the new element, drop the old one — never recompute."

🧠
Never forget: variable-size windows grow the right edge and shrink the left while a condition holds — same idea, dynamic bounds.

⬅️ Reverse Lookup in 1D (Suffix Scan) scan from the right

Sometimes the answer for each index depends on what's to its right. Scan right→left and precompute a suffix array.

💡 Intuition

Look backward to see forward: build rightMax[i] = max(a[i..n−1]) by scanning from the end. Then "the max to the right of index i" is rightMax[i+1] in O(1). Array [3,7,2,8,5] → rightMax [8,8,8,8,5].
scan i = n−1 → 0→rightMax[i]=max(a[i], rightMax[i+1])

↙️ Reverse Lookup in 2D (Suffix Matrix) bottom-right scan

The 2D version: precompute, for each cell, an aggregate of the submatrix to its bottom-right by scanning from the bottom-right corner.

💡 Intuition

Inclusion-exclusion, mirrored: S[i][j] = a[i][j] + S[i+1][j] + S[i][j+1] − S[i+1][j+1]. Filling from the bottom-right gives every cell the sum of everything down-and-right of it. Top-left cell = the whole-matrix sum = 45.
scan bottom-right → top-left→S = self + below + right − diag
🔒 Keep forever: "2D suffix sum mirrors 1D — add below & right, subtract the double-counted diagonal."

⚡ Processing Queries Efficiently (2D Prefix Sum) O(1) submatrix sum

Precompute a 2D prefix-sum matrix so any submatrix sum is answered with four lookups — no matter how many queries.

💡 Intuition

Four corners: build P[i][j] = sum of the rectangle from (0,0) to (i,j). Then the sum of submatrix (r1,c1)→(r2,c2) = P[r2][c2] − P[r1−1][c2] − P[r2][c1−1] + P[r1−1][c1−1]. Query (1,1)→(2,2) = 28.
build P[][] once→query = big − top − left + corner→O(1)
🔒 Keep forever: "2D range-sum queries = prefix matrix + inclusion-exclusion of four corners."

🔍 A Special Searching Problem sorted matrix staircase

Search a matrix whose rows and columns are both sorted. Starting from the top-right corner, each comparison eliminates a whole row or column.

💡 Intuition

Staircase from the corner: begin at the top-right. If it's larger than the target, move left (this column can't help). If smaller, move down. Each step drops a row or column → O(n+m). Searching 9 → path 11 → 7 → 8 → 9 ✓.
start top-right→bigger? go left·smaller? go down

🪣 Maximum Gap (Bucketing) pigeonhole

Find the largest gap between consecutive elements of the sorted array — in O(n), without fully sorting, using buckets.

💡 Intuition

Gaps live between buckets: spread n numbers into ~n buckets of equal width. By pigeonhole, the max gap must be at least the bucket width, so it spans across buckets — compare each bucket's min with the previous bucket's max. [1,10,5,3,8] → max gap 3.
bucket width = range/(n−1)→place into buckets→gap = nextMin − prevMax
🔒 Keep forever: "Max gap = bucketing + pigeonhole; the biggest gap is between buckets, not inside one."

🔀 Array Rearrangement (Max-Min Form) two pointers

Rearrange a sorted array into max, min, 2nd-max, 2nd-min, … alternating pattern using two pointers.

💡 Intuition

Grab from both ends: with the array sorted, alternate taking the current largest (right pointer) and smallest (left pointer). [1,2,3,4,5,6] → [6,1,5,2,4,3]. (An in-place O(1)-space version encodes both values in one slot via modular arithmetic.)
left=0, right=n−1→take right, then left, alternate

🎛️ Difference Array (Alternative Representation) O(1) range update

Represent an array by its consecutive differences so a whole range can be updated in O(1); a final prefix sum reconstructs the array.

💡 Intuition

Mark the edges, fill later: to add x to range [l, r], just do diff[l] += x and diff[r+1] −= x — O(1) per update. After all updates, a prefix sum of diff[] rebuilds the final array. Two range-adds on [0,0,0,0,0] → [3,8,8,5,0].
update [l,r]+x → diff[l]+=x, diff[r+1]−=x→prefix-sum diff → final array
🔒 Keep forever: "Difference array: range updates in O(1) at the two ends, then one prefix-sum to materialize."
