🔎 The Prefix Match Problem motivation

Given a dictionary, answer many queries: "how many / which words start with this prefix?" Scanning every word every time is wasteful.

💡 Intuition

Why a trie? To match prefix "ap" naively, you re-scan the first letters of every word — O(N·L) per query, and you keep re-walking the same shared letters. A trie stores each shared prefix once as a path, so a query just walks that path.
naive: check each word's prefix→shared letters re-scanned→trie shares prefixes → walk once
🔒 Keep forever: "Words that share a prefix should share a path — that's the whole idea of a trie."

🌱 Introduction to Tries prefix tree

A trie is a tree where each edge is a character and each root→node path spells a prefix. An end flag marks where a real word finishes.

💡 Intuition

One path per prefix: insert cat, car, card, dog. "cat" and "car" share the branch c → a, then split at t vs r. Green-ringed nodes are word ends. No prefix is ever stored twice.
root = empty prefix→edge = one character→🟢 ring = end of a word
🔒 Keep forever: "A node = a prefix. Its children = the next possible letters. The ring = a word ends here."
Press play to grow the trie from cat, car, card, dog.
🐢 🐇
🧠
Never forget: shared prefixes = shared paths. Green ring ≠ leaf — "car" ends inside the branch that continues to "card".

🎯 Prefix Search in a Trie O(L)

To find everything under a prefix, walk the prefix path once — then the whole subtree below is your answer set.

💡 Intuition

Walk then collect: search "car" — follow c → a → r. If any letter is missing, no word has that prefix (return none). If you land safely, every word in that node's subtree starts with "car" → here car, card.
walk prefix chars→missing edge → no match·landed → subtree = answers
🔒 Keep forever: "Prefix search = walk the path; the subtree under the landing node is the answer set."
Trie of [cat, car, card, cup, dog]. Search prefix "car".
Press play to walk "car" and light up its subtree.
🐢 🐇
🧠
Never forget: "does word exist" needs isEnd at the landing node; "does prefix exist" just needs to arrive there.

➕ Insertion in a Trie O(L)

Walk the word letter by letter: reuse an edge if it exists, else create a new node. Mark the final node as an end.

💡 Intuition

Reuse or branch: insert to, tea, ten, in, inn. When "ten" arrives, t → e already exists (from "tea"), so we reuse it and only add the new n. Green pops = newly created nodes; blue = reused.
for each char→child exists? reuse·else create node→mark last isEnd
🔒 Keep forever: "Insert = descend, creating nodes only for letters that don't exist yet, then flag the end."
Press play to insert to, tea, ten, in, inn one by one.
🐢 🐇
🧠
Never forget: "inn" reuses all of "in" and only adds a second n. Nothing is duplicated — that's the memory win.
insert(word){ Node cur=root;
  for(ch : word){ if(cur.child[ch]==null) cur.child[ch]=new Node(); cur=cur.child[ch]; }
  cur.isEnd=true; }

🗑️ Deletion in a Trie prune carefully

Unmark the word's end flag, then prune dead nodes bottom-up — but only nodes that have no children and aren't another word's end.

💡 Intuition

Cut only dead branches: from [tea, ten, to] delete "tea". Clear the end flag on the final a. Now walk back up: a has no children → remove it. But e still has child n (for "ten") → stop. "ten" and "to" survive untouched.
clear isEnd on last node→prune leaf if no child & not end·stop at a shared node
🔒 Keep forever: "Delete = unflag the end, then delete childless non-end nodes on the way up — stop at any fork."
Press play to delete "tea" while keeping ten and to.
🐢 🐇
🧠
Never forget: never blindly delete the path — a node may be shared. Only prune if it's childless AND not an end.

🔑 Shortest Unique Prefixes count on nodes

Give each word the shortest prefix that no other word shares. Store a pass-count on every node; walk down until the count drops to 1.

💡 Intuition

Walk to the first "1": insert words and increment a counter on each node visited. A count of 1 means only one word passes here — so the prefix so far is unique. For [zebra, dog, duck, dove]: z→"z", d is shared by 3 so descend.
insert, count passes per node→walk word down→stop when count == 1
🔒 Keep forever: "Shortest unique prefix = the path up to the first node with pass-count 1."
Numbers on nodes = how many words pass through. Walk each word to its first "1".
Press play to derive each word's shortest unique prefix.

🧠
Never forget: the pass-count trick powers autocomplete disambiguation and "shortest distinguishing prefix" problems.

🔢 Storing Binary Numbers in a Trie bit-trie

Treat each number as a fixed-width bit-string (MSB first) and insert it like a word over the alphabet {0, 1}. This "bit-trie" unlocks XOR tricks.

💡 Intuition

Numbers are just words of 0s and 1s: insert 3, 10, 5 as 4-bit strings 0011, 1010, 0101. Every node has at most two children (bit 0 / bit 1). Depth = number of bits. Now bitwise decisions become a top-down walk.
fix width (MSB→LSB)→insert bits like chars→each node ≤ 2 children
🔒 Keep forever: "A binary trie is a trie over {0,1} — go left for a 0 bit, right for a 1 bit."
Insert 3 = 0011, 10 = 1010, 5 = 0101 (4 bits, MSB first).
Press play to insert three numbers as bit-paths.
🐢 🐇
🧠
Never forget: always use a fixed width so every number reaches the same depth — that's what makes bitwise comparisons align.

⚡ Maximum XOR in an Array greedy bit-trie

Put all numbers in a bit-trie. For a number, greedily walk toward the opposite bit at each step — opposite bits make XOR's bit a 1, maximizing the result.

💡 Intuition

Chase opposite bits: XOR is 1 exactly when bits differ. So from the top bit down, always try to go to the child holding the opposite bit; only fall back to the same bit if the opposite branch is empty. The path you take spells the best partner.
insert all numbers→per number: prefer opposite bit→track max XOR
🔒 Keep forever: "Max XOR = greedily grab the opposite bit at every level of the bit-trie."
Array [3, 10, 5, 25, 2, 8] (5 bits). Querying 25 = 11001 for its best partner.
Press play to build the bit-trie and greedily maximize XOR for 25.
🐢 🐇
🧠
Never forget: insert-then-query each number → overall max XOR in O(N·bits). Here the max pair is 25 ⊕ 5 = 28.
maxXor(x){ Node cur=root; int res=0;
  for(b=BITS-1; b>=0; b--){
    int bit=(x>>b)&1, want=bit^1;
    if(cur.child[want]!=null){ res|=(1<<b); cur=cur.child[want]; }
    else cur=cur.child[bit];
  } return res; }
