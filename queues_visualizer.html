🚶 What is a Queue? FIFO

A queue is a First-In-First-Out line — add at the rear, remove from the front.

💡 Intuition

A line at the ticket counter: newcomers join at the back (enqueue) and the person at the front is served first (dequeue). No cutting — order of arrival is order of service.
enqueue → add at rear·dequeue → remove from front·peek → read front
🔒 Keep forever: "Front leaves first, rear joins last — First In, First Out."

int f = q.peek();       // read front
q.dequeue();           // remove front

🔄 Circular Queue Wrap-around

A fixed array reused in a ring — front & rear wrap with modulo so freed slots are recycled.

💡 Intuition

Seats around a round table: when rear reaches the last slot, it wraps back to slot 0 (if free). No shifting, no wasted space — the array is a loop and both pointers chase each other with (i+1) % capacity.
rear = (rear+1) % cap·front = (front+1) % cap·full when count == cap
🔒 Keep forever: "Modulo turns a flat array into a ring — indices wrap, space is reused."
Capacity 5: enqueue 10,20,30, dequeue, enqueue 40,50,60 — watch 60 wrap to slot 0.

🧠
Never forget: distinguish full vs empty with a count (or leave one slot gap). Both indices advance modulo capacity.
enqueue(x){ rear=(rear+1)%cap; a[rear]=x; count++; }
dequeue(){ front=(front+1)%cap; count--; }

📥 Design a Queue using Stacks Costly dequeue

Two stacks fake a queue: push into an in stack; to dequeue, flip everything into an out stack.

💡 Intuition

Pour between two glasses: new items pile into the "in" stack. When you need the front, pour "in" into "out" — the reversal puts the oldest item on top of "out". Keep popping "out" until it's empty, then pour again.
enqueue → push in·dequeue: out empty? move all in→out·pop out
🔒 Keep forever: "Reversing a stack once makes its top the queue's front — amortized O(1)."
enqueue 1,2,3 → dequeue → enqueue 4 → dequeue.

Never forget: each element is moved at most once from in→out → amortized O(1) per op, even though a single dequeue can be O(n).
enqueue(x){ in.push(x); }
dequeue(){ if (out.isEmpty()) while(!in.isEmpty()) out.push(in.pop());
           return out.pop(); }

📤 Design a Queue using Stacks II Costly enqueue

The mirror approach: do the work on enqueue so the front always sits on top — dequeue is instant.

💡 Intuition

Always keep the eldest on top: to add a new item, temporarily pour the main stack into a helper, drop the newcomer at the bottom, then pour back. Now the oldest element is always on top, so dequeue is a single pop.
enqueue: move main→helper, push x, move back·dequeue: pop main (front on top)
🔒 Keep forever: "Pay on enqueue to keep the front on top — dequeue/peek become O(1)."
enqueue 1, 2, 3 (front stays on top), then dequeue.
main (front on top)
helper
Press play. Enqueue keeps the oldest element on top.
🐢 🐇
🧠
Never forget: choose the costly-enqueue vs costly-dequeue design by which operation you call more often.
enqueue(x){ while(!main.isEmpty()) help.push(main.pop());
            main.push(x);
            while(!help.isEmpty()) main.push(help.pop()); }
dequeue(){ return main.pop(); }   // front is on top

📚 Design a Stack using Queues Rotate trick

One queue behaves like a stack if, after each push, you rotate the newest item to the front.

💡 Intuition

Send everyone around the loop: enqueue the new item, then dequeue-and-re-enqueue every older item so the newcomer ends up at the front. Now a normal dequeue removes the most-recent item — that's LIFO from a FIFO queue.
push x → enqueue x→rotate (size−1) times→pop = dequeue front
🔒 Keep forever: "After pushing, rotate the queue so the newest sits at the front → pop is LIFO."
push 1, 2, 3 (rotating each time), then pop → 3.
Queue (front → rear)
Press play. Rotation puts the newest at the front.
🐢 🐇
🧠
Never forget: push is O(n) (the rotation); pop/top are O(1). One queue suffices — no second queue needed.
push(x){ q.offer(x); for(int i=0;i<q.size()-1;i++) q.offer(q.poll()); }
pop(){ return q.poll(); }   // newest is at front

🔁 Reverse a Queue Stack helper

Dequeue everything into a stack, then pop it all back — the queue comes out reversed.

💡 Intuition

A U-turn through a stack: a queue keeps order, a stack flips it. Pour the queue into a stack (front items sink to the bottom), then pour back — the last-in items now lead. Order reversed.
dequeue all → push to stack→pop all → enqueue back
🔒 Keep forever: "Queue → stack → queue flips FIFO order into reverse."

🌳 Level Order Traversal (BFS) Queue-driven

Visit a tree level by level using a queue — the classic breadth-first search.

💡 Intuition

Ripples in a pond: start with the root in the queue. Repeatedly dequeue a node, visit it, and enqueue its children. The FIFO order guarantees you finish each level before the next — like ripples spreading outward.
enqueue root→dequeue & visit→enqueue its children
🔒 Keep forever: "A queue processes a tree level by level — that's BFS."
Tree traversal order → 1, 2, 3, 4, 5, 6.
Queue
Press play to walk the tree breadth-first.
🐢 🐇
🧠
Never forget: track queue size at each step to separate levels. BFS also finds shortest paths in unweighted graphs.
q.offer(root);
while(!q.isEmpty()){
  Node n = q.poll(); visit(n);
  if(n.left!=null) q.offer(n.left);
  if(n.right!=null) q.offer(n.right);
}

↔️ Doubly Ended Queue (Deque) Both ends

A deque lets you add and remove from both the front and the back — the most flexible linear structure.

💡 Intuition

A double-door hallway: people can enter or leave from either end. That flexibility makes a deque act as a stack, a queue, or the engine behind sliding-window maximums (next!).
pushFront / pushBack·popFront / popBack·O(1) at both ends
🔒 Keep forever: "A deque = add/remove at either end — stack + queue in one."

📈 Maximum in Sliding Window Monotonic deque

Report the max of every window of size k in O(n) using a decreasing deque of indices.

💡 Intuition

Bouncers keep only contenders: keep a deque of indices whose values are decreasing. Before adding a new element, evict smaller ones from the back (they can never be the max while it's around). Drop the front if it slid out of the window. The front is always the window's maximum.
pop back while < current·push current index·pop front if out of window·front = max
🔒 Keep forever: "Keep a decreasing deque; its front is the window max — each index enters/leaves once."
Array [1,3,-1,-3,5,3,6,7], k=3 → maxima [3,3,5,5,6,7].

Never forget: store indices (not values) so you can detect when the max slides out of the window.
for(int i=0; i<n; i++){
  while(!dq.isEmpty() && a[dq.peekLast()] <= a[i]) dq.pollLast();
  dq.offerLast(i);
  if(dq.peekFirst() == i-k) dq.pollFirst();     // out of window
  if(i >= k-1) res.add(a[dq.peekFirst()]);       // front = max
}

⚡ Maximum in Sliding Window II Block prefix/suffix

A different O(n) method: split into blocks of k, precompute block prefix-max and suffix-max arrays.

💡 Intuition

Meet in the middle of two blocks: any window of size k spans at most two adjacent blocks. Precompute left[i] = max from the block start up to i, and right[i] = max from i to the block end. Then window max = max(right[l], left[r]) — one lookup, no deque.
left = prefix max per block·right = suffix max per block→window = max(right[l], left[r])
🔒 Keep forever: "A window straddles two blocks — combine one block's suffix-max with the next's prefix-max."
Same array, k=3 → build left[] & right[], then answer each window.

➖ First Negative Integer in Every Window Index queue

Track a queue of negative-number indices — its front is the first negative in the current window.

💡 Intuition

A waiting list of negatives: keep a queue of indices where the value is negative. As the window slides, drop front indices that fell out of range. Whatever's left at the front is the first negative; if the queue is empty, the window has none.
negative? enqueue its index·front out of window? dequeue·answer = a[front] or 0
🔒 Keep forever: "Queue the negatives' indices; the front is the first negative still in the window."
Array [12,-1,-7,8,-15,30,16,28], k=3 → [-1,-1,-7,-15,-15,0].

  if(a[i] < 0) q.offer(i);
  if(!q.isEmpty() && q.peek() <= i-k) q.poll();  // out of window
  if(i >= k-1) res.add(q.isEmpty() ? 0 : a[q.peek()]);
}
