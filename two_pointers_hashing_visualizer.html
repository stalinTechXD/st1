➕ Pair Sum I — Unsorted (Hashing) O(n)

Find two numbers that add to a target in an unsorted array — one pass with a hash set.

💡 Intuition

The name-tag desk: as each guest arrives you ask "has your partner (target − you) already checked in?" If yes, pair found. If not, drop your own tag in the box. One walk down the line finds the pair.
for each x→need = target − x→need in set? pair!/else add x
🔒 Keep forever: "Remember what you've seen; each element asks if its complement already arrived."

🐢 🐇
🧠
Never forget: hashing turns "search for a partner" from O(n) into O(1). Works even when the array is unsorted.
Set<Integer> seen = new HashSet<>();
for (int x : a) {
  if (seen.contains(target - x)) return {target - x, x};
  seen.add(x);
}

➕ Pair Sum II — Sorted (Two Pointers) O(n)

In a sorted array, find all pairs summing to a target using pointers from both ends.

💡 Intuition

The see-saw again: smallest on the left, largest on the right. Sum too big? pull the right finger in. Too small? push the left finger out. Equal? record it and step both inward.
l=0, r=n−1→sum>T? r−−/sum<T? l++/== ? record, l++ r−−
🔒 Keep forever: "Sorted + two pointers = converge from both ends, no extra memory."
Sorted [1,2,3,4,6,7,8,9], target 10 → all pairs.
Press play to find every pair summing to 10.
🐢 🐇
🧠
Never forget: hashing (Pair Sum I) uses O(n) space; sorted two-pointer uses O(1) space. Pick by whether the array is already sorted.
int l=0, r=n-1;
while (l < r) {
  int s = a[l] + a[r];
  if (s == target) { record(a[l], a[r]); l++; r--; }
  else if (s < target) l++; else r--;
}

➖ Pair with Given Difference Same-direction 2-ptr

In a sorted array, find pairs whose difference equals d — both pointers move forward.

💡 Intuition

The measuring caliper: two jaws slide rightward. Gap too small? open the front jaw (j++). Gap too big? drag the back jaw forward (i++). When the gap equals d, you've caught a pair.
i, j both →→gap<d? j++/gap>d? i++/==? record
🔒 Keep forever: "For differences, both pointers march forward — open or close the gap toward d."
Sorted [1,3,5,8,9,12], difference d = 3.
Press play to find pairs with difference 3.
🐢 🐇
🧠
Never forget: sums use opposite ends (l,r converge); differences use same direction (i,j both advance). Keep i<j.
int i=0, j=1;
while (j < n) {
  int diff = a[j] - a[i];
  if (diff == d && i != j) { record(a[i], a[j]); i++; j++; }
  else if (diff < d) j++; else i++;
}

📦 Subarray Sum = K (Prefix + Hash) Handles negatives

Find a contiguous subarray summing to K — even with negative numbers — using prefix sums + a hash map.

💡 Intuition

Mile markers on a road: record the running total at every step. A stretch sums to K whenever current − K was a total you've seen before — the road between those two markers is exactly K long.
prefix += a[i]→seen (prefix − K)?→yes → subarray!/store prefix
🔒 Keep forever: "A subarray = difference of two prefix sums; hash the sums you've seen."
Array [3, 4, 7, 2, -3, 1, 4, 2], K = 10.
prefix→idx:
Press play. Running total meets a seen (prefix − K).
🐢 🐇
🧠
Never forget: seed the map with {0 → −1} so subarrays starting at index 0 are found. Sliding window only works when all values are positive.
map.put(0, -1); int prefix = 0;
for (int i=0; i<n; i++) {
  prefix += a[i];
  if (map.containsKey(prefix - K)) return {map.get(prefix-K)+1, i};
  map.putIfAbsent(prefix, i);
}

3️⃣ Triplet Sum (3-Sum) Sort + 2-ptr

Find triples a + b + c = target by fixing one element and two-pointering the rest.

💡 Intuition

Pin one, chase two: sort the array. Fix the first number, then the problem shrinks to "pair sum = target − fixed" on the remaining sorted tail — solved with the see-saw two pointers. Slide the pin across the array.
sort→fix i→two-pointer for target−a[i]
🔒 Keep forever: "k-sum = fix one, recurse into (k−1)-sum. 3-sum = fix + pair sum."
Sorted [-4,-1,-1,0,1,2], target 0.
Press play. Pin i (yellow); l,r chase the rest.
🐢 🐇
🧠
Never forget: sorting first is what unlocks the inner two-pointer and makes skipping duplicates easy. Overall O(n²).
sort(a);
for (int i=0; i<n-2; i++) {
  int l=i+1, r=n-1;
  while (l<r) {
    int s = a[i]+a[l]+a[r];
    if (s==target){ record(); l++; r--; }
    else if (s<target) l++; else r--;
  }
}

4️⃣ Quadruplet Sum (4-Sum) Sort + 2 fixed + 2-ptr

Find quadruples summing to target — fix two elements, two-pointer the remaining two.

💡 Intuition

Pin two, chase two: the exact same ladder as 3-sum, one rung deeper. Fix i and j, then two-pointer for target − a[i] − a[j]. Every k-sum is just more nested pins over one final pair scan.
🔒 Keep forever: "4-sum = fix two, then pair sum. The pattern nests for any k."
Sorted [-2,-1,0,0,1,2], target 0.
Press play. Pins i,j (yellow); l,r chase the rest.
🐢 🐇
🧠
Never forget: 2-sum O(n) → 3-sum O(n²) → 4-sum O(n³). Each extra fixed element adds one factor of n.
sort(a);
for i: for j=i+1: {
  int l=j+1, r=n-1, need=target-a[i]-a[j];
  while (l<r) {
    int s=a[l]+a[r];
    if (s==need){ record(); l++; r--; }
    else if (s<need) l++; else r--;
  }
}

▭ Distinct Rectangles from Points Pair hashing

Count axis-aligned rectangles among grid points: two rows sharing the same pair of columns form one.

💡 Intuition

Matching fence posts: a rectangle needs two rows that each have posts in the same two columns. So compare rows pairwise; every pair of shared columns between two rows is one rectangle. c shared columns → C(c,2) rectangles.
for each row-pair→count shared columns c→add C(c,2)
🔒 Keep forever: "Two rows + two shared columns = one rectangle. Count shared column-pairs."
Points on a 4×4 grid. Watch matching column-pairs light up as rectangles.
Press play to count distinct rectangles.
🐢 🐇
🧠
Never forget: hashing column-pairs per row makes this O(rows × cols²) instead of checking all 4-point combos.
for each pair of rows (r1, r2):
  c = number of columns where BOTH rows have a point;
  rectangles += c*(c-1)/2; // choose 2 shared columns

🪟 Longest Substring Without Repetition Sliding Window

Find the longest run of distinct characters using an expanding/shrinking window and a last-seen map.

💡 Intuition

A no-repeats hallway: extend the window's right edge one char at a time. The moment you re-enter a character already inside the window, yank the left edge just past its previous spot. The window always holds only distinct characters; track its longest length.
grow r→repeat inside? jump l past it→update best = r−l+1
🔒 Keep forever: "Grow right; on a repeat, snap left past the old copy; track the max."
String "abcabcbb" → longest = 3 ("abc").
last seen:
Press play. Window holds only distinct characters.
🐢 🐇
🧠
Never forget: left only ever moves right → each char enters/leaves once → O(n). Never move left backward.
int l=0, best=0; Map<Char,Integer> last=new HashMap<>();
for (int r=0; r<n; r++) {
  if (last.containsKey(s[r]) && last.get(s[r]) >= l) l = last.get(s[r]) + 1;
  last.put(s[r], r);
  best = max(best, r - l + 1);
}

🎯 Smallest Window with All Characters Min Window

Find the shortest substring of s that contains every character of t — expand to cover, then shrink to minimize.

💡 Intuition

Collecting a shopping list: walk right adding items until your cart has everything on the list. Then walk the left edge inward, dropping anything you can spare, to make the shortest valid stretch. Record the smallest complete window seen.
expand r until valid→shrink l while still valid→record smallest
🔒 Keep forever: "Grow to satisfy, shrink to minimize — track need vs have counts."
s = "ADOBECODEBANC", t = "ABC" → answer "BANC".
Press play. Cover all of ABC, then shrink.
🐢 🐇
🧠
Never forget: track formed (how many required chars are fully satisfied). Window is valid when formed == required.
expand r: window[s[r]]++; if (window[s[r]]==need[s[r]]) formed++;
while (formed==required) {           // valid → try to shrink
  if (r-l+1 < best) best = r-l+1;
  window[s[l]]--; if (window[s[l]]<need[s[l]]) formed--; l++;
}

🧮 Minimize the Expression Sort + Greedy

Split all digits into two numbers so their sum is smallest — sort ascending, then deal them alternately.

💡 Intuition

Fair card deal: to keep two numbers small, the smallest digits must sit in the highest place values. Sort ascending, then deal digits one-to-each like cards: the two smallest become leading digits, and every place value gets the smallest available digit.
sort digits ↑→deal alternately to A, B→sum A + B is minimal
🔒 Keep forever: "Small digits into high place values → sort, then alternate to two numbers."
Digits [6, 8, 4, 5, 2, 3] → minimal sum split.
Press play. Sort, then deal digits into two numbers.
🐢 🐇
🧠
Never forget: the greedy proof — swapping a bigger digit into a higher place only increases the sum. Sorting makes the greedy optimal.
sort(digits);              // ascending
for (int i=0; i<n; i++)
  if (i%2==0) numA = numA*10 + digits[i];
  else        numB = numB*10 + digits[i];
return numA + numB;       // minimal sum

🔱 Specific Prime Factorization (SPF Sieve) O(log n) per query

Precompute each number's smallest prime factor, then factorize any number by repeatedly dividing by its SPF.

💡 Intuition

A pre-labelled toolbox: a sieve stamps every number with its smallest prime factor once. To factorize N, just read its stamp, divide, and repeat on the quotient — each division peels off the next prime instantly, no trial division needed.
sieve: mark SPF of every number→N /= SPF[N]→repeat until 1
🔒 Keep forever: "Sieve the smallest prime factor once; then factorizing is just repeated look-up-and-divide."
SPF sieve for 2..36, then factorize 36 → 2 × 2 × 3 × 3.
Press play. Build SPF, then peel 36 into primes.
🐢 🐇
🧠
Never forget: the sieve costs O(n log log n) once; afterward each number factorizes in O(log n) look-ups — perfect for many queries.
// build once
for (int i=2; i<=N; i++) if (spf[i]==0)
  for (int j=i; j<=N; j+=i) if (spf[j]==0) spf[j]=i;
// factorize any x ≤ N
while (x > 1) { print(spf[x]); x /= spf[x]; }
