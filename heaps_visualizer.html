🏔️ What is a Heap? complete tree + array

A heap is a complete binary tree stored in an array, obeying the heap property: in a max-heap, every parent ≥ its children (so the max sits at the root).

💡 Intuition

Array is the tree: no pointers needed — node i's children are 2i+1 and 2i+2, and its parent is (i−1)/2. "Complete" (filled left-to-right) keeps the array gap-free and the height ≈ log n. The root is always the extreme (max here).
children of i = 2i+1, 2i+2·parent of i = (i−1)/2·root = max

🔼 Building a Max-Heap I insert + sift-up · O(n log n)

Insert elements one at a time. Each new value goes at the end, then sifts up — swapping with its parent while it's larger.

💡 Intuition

Bubble the newcomer up: add the value as the last leaf (keeps it complete), then compare with its parent and swap upward until the parent is bigger or it becomes the root. Doing this for all n values builds the heap in O(n log n).
append at end→while > parent: swap up→repeat for each element

🏗️ Building a Max-Heap II bottom-up heapify · O(n)

Start with the array as-is and sift down every internal node, from the last parent up to the root. Surprisingly, this is only O(n).

💡 Intuition

Fix small subtrees first: leaves are already valid heaps. Process parents from the last one backward, pushing each down into its (already-heapified) subtree. Most nodes are near the bottom with tiny sift distances → the total is O(n), beating repeated insertion.
start at last parent (n/2−1)→sift-down each, going up→O(n) total

⚙️ Heap Operations insert · extract-max

The two core operations: insert (append + sift-up) and extract-max (take the root, move last to root, sift-down). Both O(log n).

💡 Intuition

Root out, patch the hole: the max is always the root. To remove it, swap it with the last leaf, drop the leaf, then sift the new root down — repeatedly swapping with the larger child until order is restored.
insert: append + sift-up·extract: root↔last, pop, sift-down

🎫 Priority Queue heap in action

A priority queue always serves the highest-priority item next. A heap is its natural implementation: push = insert, poll = extract-top.

💡 Intuition

VIP line: unlike a normal FIFO queue, a PQ dequeues by priority, not arrival order. Back it with a heap and every push/poll is O(log n) while peek at the best is O(1). Here a max-heap PQ always hands back the largest value.
push → sift-up·poll → remove root, sift-down·peek → root O(1)

📊 Heap Sort O(n log n) · in-place

Build a max-heap, then repeatedly swap the root (current max) to the end and shrink the heap, sifting down. The array sorts itself ascending.

💡 Intuition

Peel the max to the back: once it's a max-heap, the largest is at index 0. Swap it with the last unsorted slot (locking it in place), shrink the heap by one, and sift the new root down. Repeat until the heap is empty — a sorted array remains, using no extra memory.
build max-heap→swap root ↔ last, shrink→sift-down, repeat
🔒 Keep forever: "Heap sort = build a max-heap, then extract-max into the tail repeatedly — in-place O(n log n)."

📍 K Closest Points to Origin max-heap of size k

Keep a max-heap of size k holding the closest points so far; if a new point is nearer than the heap's farthest, swap it in.

💡 Intuition

Guard the top-k: a max-heap keyed by distance keeps the worst of the current best-k at the root. For each point, if it's closer than that worst, pop the worst and push the newcomer. After all points, the heap holds the k closest. O(n log k). Here k=2.
push first k→closer than root? replace→heap = k closest

🪢 Tying Ropes (Min Cost to Connect) min-heap greedy

Repeatedly join the two shortest ropes; the cost of each join is their combined length. A min-heap always surfaces the two smallest.

💡 Intuition

Cheapest joins first: joining costs the sum of the two ropes, and longer ropes get re-counted in every later join — so always merge the two smallest to keep re-counting cheap. Pop two mins, push their sum, add to total. This Huffman-style greedy is optimal. Ropes [4,3,2,6] → 29.
min-heap of lengths→pop two smallest, cost += sum→push sum, repeat

🔗 Merge K Sorted Arrays min-heap of heads

Put the first element of each array into a min-heap; repeatedly pop the smallest and push the next element from that same array.

💡 Intuition

Smallest head wins: the next value in the merged output is the minimum among all current array heads. A min-heap holding one candidate per array gives that in O(log k). Pop it, advance that array, push its new head. Total O(N log k).
push each array's head→pop min → output→push next from that array

➕ K Smallest Sum Pairs min-heap frontier

From two sorted arrays, find the k pairs (one from each) with the smallest sums — without generating all n×m pairs.

💡 Intuition

Grow a frontier: the smallest sum is always (nums1[0], nums2[0]). From any popped pair (i,j), the next candidates are (i+1,j) and (i,j+1). A min-heap ordered by sum always yields the next-smallest pair. Here [1,7,11] × [2,4,6], k=3 → (1,2),(1,4),(1,6).
seed heap with (0,0)→pop min sum → output→push (i+1,j) & (i,j+1)

💻 K Smallest Pairs — Implementation the code

A common tidy variant: seed the heap with only (nums1[i], 0) for each i, then from a popped (i,j) push just (i, j+1). Fewer entries, no visited set needed.

💡 Intuition

One pointer per row: think of an n×m sum-matrix sorted along each row. Start with each row's first column in the heap. Popping (i,j) only ever needs its right neighbor (i,j+1) — each row advances independently, so no duplicates arise. Same k pairs, cleaner bookkeeping.
push (i,0) for all i→pop min → output→push (i, j+1) only

🔳 Kth Smallest in a Sorted Matrix min-heap merge

In a matrix with rows and columns sorted ascending, treat each row as a sorted list and merge — the kth popped value is the answer.

💡 Intuition

Merge k rows, stop at k: seed a min-heap with each row's first element. Pop the smallest and push the next element in that row. The kth pop is the kth smallest overall. Here k=8 in a 3×3 matrix → 13.
push row heads→pop min, push right neighbor→kth pop = answer

🗓️ Task Scheduling (with Cooldown) max-heap greedy

Identical tasks must be at least n slots apart. Minimize total time by always running the most frequent remaining task next.

💡 Intuition

Spread the busiest: the task with the highest remaining count is the bottleneck, so schedule it as early as cooldown allows. Each cycle of n+1 slots, pop the top counts from a max-heap, run them once, and re-add those still remaining. Tasks AAABBB, n=2 → 8 (A B idle A B idle A B).
max-heap of counts→run top n+1 distinct per cycle→idle if none ready

✨ Numbers with Limited Prime Factors I min-heap generation

Generate numbers whose only prime factors come from a given set (e.g. {2,3,5} — the "ugly numbers"). A min-heap grows them in order.

💡 Intuition

Grow by multiplying: start the heap with 1. Pop the smallest, output it, and push it multiplied by each allowed prime (2, 3, 5). A seen set avoids duplicates (6 = 2·3 = 3·2). The k-th popped value is the k-th such number. Primes {2,3,5}, k=10 → 12.
heap = {1}→pop min → output→push value×each prime (dedupe)

🌟 Numbers with Limited Prime Factors II multi-pointer DP

The O(n·k) pointer method (no heap): keep one pointer per prime into the sequence built so far, and always take the smallest next candidate.

💡 Intuition

Pointers instead of a heap: build the array dp in order. For each prime keep an index p; its candidate is dp[p]×prime. The next number is the min of these candidates; advance every pointer that produced it (handles duplicates). Same sequence as the heap, O(n·k), no dedupe set. Primes {2,3,5}, 10th → 12.
dp[0]=1, pointer per prime→next = min(dp[pᵢ]×primeᵢ)→advance tying pointers
