🔗 What is a Linked List? Foundation

A chain of nodes — each holds a value and a pointer to the next. No fixed size, no contiguous memory.

💡 Intuition

A treasure hunt: each clue (node) holds a prize (value) and directions to the next clue (next pointer). You follow the trail from head until a clue points to nothing (null).
node = value + next·start at head·follow until null
🔒 Keep forever: "Each node points to the next — follow from head to null."
A list: 3 → 7 → 1 → 9 → null.

class Node { int val; Node next; }
Node cur = head;
while (cur != null){ visit(cur); cur = cur.next; }

🛠️ Basic Operations Insert · Delete

Insert at head, insert at tail, and delete a node — all by rewiring next pointers.

💡 Intuition

Rerouting a train track: to add a car, point the previous node to the newcomer and the newcomer to what followed. To delete, just skip a node by pointing its predecessor past it. It's all pointer rewiring — no shifting.
insert head: new.next = head·insert tail: tail.next = new·delete: prev.next = cur.next
🔒 Keep forever: "Everything is pointer rewiring — link around what you add or remove."
Start 2→3→4. Insert 1 at head, insert 5 at tail, delete 3.
List
Press play to insert & delete by rewiring pointers.
🐢 🐇
🧠
Never forget: keep a reference to prev when deleting. A dummy/sentinel head simplifies edge cases (deleting the first node).
insertHead(x){ Node n=new Node(x); n.next=head; head=n; }
delete(prev){ prev.next = prev.next.next; }   // skip the node

🎯 Middle Node (Slow & Fast) Two pointers

Find the middle in one pass — a slow pointer steps by 1, a fast pointer by 2.

💡 Intuition

Two runners on a track: the fast runner covers twice the distance. When the fast one reaches the end, the slow one is exactly halfway — the middle node, without ever counting the length.
slow += 1·fast += 2→fast at end ⇒ slow = middle
🔒 Keep forever: "Fast goes twice as fast — when it ends, slow is the middle."
List 1→2→3→4→5→6→7 → middle is 4.
List
Press play. Slow lands on the middle.
🐢 🐇
🧠
Never forget: this "tortoise & hare" pattern also detects cycles and finds the k-th-from-end. One pass, O(1) space.
Node slow=head, fast=head;
while (fast != null && fast.next != null){ slow=slow.next; fast=fast.next.next; }
return slow; // middle

🗑️ Delete Nth Node from End Gap pointers

Delete the n-th node from the end in one pass by keeping two pointers a fixed gap apart.

💡 Intuition

A measuring stick: advance a lead pointer n steps ahead, then move both together. When the lead hits the end, the trailing pointer sits just before the target — the n-th from the end. Skip it.
fast advances n steps→move both until fast at end→slow.next = slow.next.next
🔒 Keep forever: "Open a gap of n, then walk together — the trailing pointer finds the target."
List 1→2→3→4→5, n=2 → delete node 4.
List
Press play. The gap reveals the node to delete.
🐢 🐇
🧠
Never forget: use a dummy head so deleting the first node is uniform. The gap must be exactly n edges.
fast = dummy; for(i=0;i<=n;i++) fast=fast.next; slow=dummy;
while(fast!=null){ slow=slow.next; fast=fast.next; }
slow.next = slow.next.next;   // delete

🔄 Reverse a List (Iterative) prev · curr · next

Walk the list flipping each node's next to point backward — three pointers, one pass.

💡 Intuition

Turning the arrows around: hold prev (already-reversed part), curr (node to flip), and stash next before you lose it. Point curr back to prev, then shuffle all three forward. The old tail becomes the new head.
save next→curr.next = prev→prev = curr, curr = next
🔒 Keep forever: "Flip curr → prev, then slide the trio forward. Old tail = new head."
Reverse 1→2→3→4 into 4→3→2→1.
List
Press play. Each arrow flips backward.
🐢 🐇
🧠
Never forget: always save next BEFORE flipping curr.next, or you lose the rest of the list. O(n), O(1).
Node prev=null, cur=head;
while(cur!=null){ Node nxt=cur.next; cur.next=prev; prev=cur; cur=nxt; }
return prev; // new head

↩️ Reverse a List (Recursive) Unwind rewire

Recurse to the end, then rewire pointers backward on the way out.

💡 Intuition

Rewire on the way back: dive all the way to the last node (the new head). As each call returns, make the next node point back at the current one (cur.next.next = cur) and cut the old forward link. The recursion unwinds, reversing the chain.
recurse to end→cur.next.next = cur→cur.next = null
🔒 Keep forever: "Reach the end, then on unwind make each next node point back."
Reverse 1→2→3→4 recursively.
List
Press play. Recursion dives, then rewires on return.
🐢 🐇
🧠
Never forget: the base case returns the last node as the new head; it bubbles all the way back up unchanged. O(n) stack space.
Node reverse(Node cur){
  if(cur==null || cur.next==null) return cur; // new head
  Node head = reverse(cur.next);
  cur.next.next = cur; cur.next = null;
  return head;
}

🪞 Palindrome Linked List Two pointers

Check if the list reads the same forwards and backwards.

💡 Intuition

Mirror check: compare the first value with the last, the second with the second-last, and so on. If every mirrored pair matches, it's a palindrome. (The O(1) trick: find the middle, reverse the second half, then compare.)
front & back pointers→compare, move inward→any mismatch ⇒ not palindrome
🔒 Keep forever: "Compare mirrored pairs from both ends — or reverse the second half for O(1) space."
List 1→2→3→2→1 → palindrome?
Press play. Compare mirrored pairs.
🐢 🐇
🧠
Never forget: the space-optimal way = middle + reverse-second-half + compare + (optionally) restore. O(n) time, O(1) space.
slow=middle(head); second=reverse(slow);
while(second!=null){ if(head.val!=second.val) return false; head=head.next; second=second.next; }
return true;

🔢 Reverse in Groups of K Block flip

Reverse every consecutive block of k nodes, leaving the rest linked.

💡 Intuition

Flipping pancakes k at a time: reverse the first k nodes, then recurse/iterate on the remainder and stitch the reversed block to it. Each group flips independently; the group heads/tails get reconnected in order.
reverse first k→recurse on the rest→connect block tail → next block head
🔒 Keep forever: "Reverse k, recurse on the rest, then link the pieces."
List 1→2→3→4→5→6, k=3 → 3→2→1→6→5→4.
List
Press play. Each group of 3 flips.
🐢 🐇
🧠
Never forget: if fewer than k nodes remain, leave them as-is (standard variant). Track each block's new head & tail to reconnect.
Node kReverse(Node head, int k){
  Node cur=head, prev=null, nxt=null; int c=0;
  while(cur!=null && c<k){ nxt=cur.next; cur.next=prev; prev=cur; cur=nxt; c++; }
  if(nxt!=null) head.next = kReverse(nxt, k);
  return prev;
}

🌀 Cycle Detection I — Does a Cycle Exist? Floyd

Detect a loop with Floyd's tortoise & hare — if the fast pointer laps the slow, there's a cycle.

💡 Intuition

Runners on a circular track: on a straight road the fast runner just reaches the end. But on a loop, the fast runner keeps circling and eventually catches the slow one from behind. A meeting means a cycle.
slow += 1, fast += 2→they meet ⇒ cycle/fast hits null ⇒ no cycle
🔒 Keep forever: "On a loop, the hare laps the tortoise — a meeting proves a cycle."
List 1→2→3→4→5 with 5 linking back to 3.
List (5 → back to 3)
Press play. Slow & fast meet inside the loop.
🐢 🐇
🧠
Never forget: O(n) time, O(1) space — no hash set needed. If fast (or fast.next) is null, the list ends → no cycle.
slow=head; fast=head;
while(fast!=null && fast.next!=null){
  slow=slow.next; fast=fast.next.next;
  if(slow==fast) return true; // cycle!
}
return false;

📍 Cycle Detection II — Find the Start Reset trick

After the pointers meet, find where the loop begins by resetting one pointer to the head.

💡 Intuition

A tidy math coincidence: once slow & fast meet, move one pointer back to the head and advance both one step at a time. The distance math works out so they meet again exactly at the cycle's entry node.
detect meeting point→one pointer → head→both +1 until they meet = start
🔒 Keep forever: "After they meet, restart one at head; step both by 1 — they meet at the loop's start."
Same list — the cycle starts at node 3.
List (5 → back to 3)
Press play to locate the cycle's entry.
🐢 🐇
🧠
Never forget: distance(head → start) == distance(meeting → start) around the loop. That's why the reset-and-walk works.
// after slow==fast:
Node p=head;
while(p!=slow){ p=p.next; slow=slow.next; }
return p; // cycle start

📏 Cycle Detection III — Loop Length Count around

Measure the cycle's length by walking one full lap from the meeting point.

💡 Intuition

One lap of the track: from the meeting node, keep one pointer fixed and send another around the loop, counting steps until it returns. That count is the cycle length — handy for removing the loop or analysis.
start at meeting node→walk until back, counting→count = loop length
🔒 Keep forever: "From the meeting point, count steps back to it — that's the loop length."
Same list — cycle 3→4→5→3 has length 3.
List (5 → back to 3)
Press play to count the loop length.
🐢 🐇
🧠
Never forget: to REMOVE the cycle, walk length L with two gap-L pointers, or set the node before the start's next = null.
Node t = meeting; int len=0;
do { t=t.next; len++; } while(t != meeting);
return len; // loop length

🔗 Merge Two Sorted Lists (Iterative) Two pointers

Zip two sorted lists into one by repeatedly attaching the smaller head.

💡 Intuition

A zipper: compare the two front nodes, splice the smaller onto the result tail, and advance that list. A dummy head keeps the code clean; when one list ends, attach the rest of the other.

🔗 Merge Two Sorted Lists (Recursive) Elegant

The same merge expressed recursively — pick the smaller head, then merge the rest.

💡 Intuition

Smaller head leads the rest: the merged list's head is the smaller of the two front nodes; its next is the merge of what remains. The recursion peels one node at a time until a list is empty.
🔒 Keep forever: "head = smaller node; head.next = merge(rest). Base case: one list empty."

Never forget: cleaner code, but O(n+m) stack depth. Iterative is safer for very long lists.
Node merge(Node a, Node b){
  if(a==null) return b; if(b==null) return a;
  if(a.val<=b.val){ a.next=merge(a.next,b); return a; }
  else { b.next=merge(a,b.next); return b; }
}

🎄 Merge K Sorted Lists Min-heap

Merge k lists at once by always pulling the smallest current head — a min-heap makes it O(N log k).

💡 Intuition

k queues, one cashier: put the head of every list into a min-heap. Repeatedly pop the smallest, append it to the result, and push that node's successor. The heap always surfaces the global minimum among all k fronts.
heap ← all k heads→pop min → output→push its next
🔒 Keep forever: "A min-heap of the k heads yields the global smallest each step — O(N log k)."

🧬 Clone a List with Random Pointers I Hash map

Deep-copy a list where each node has a random pointer — map every original node to its clone.

💡 Intuition

A translation dictionary: first pass, create a clone for each node and record original → clone in a hash map. Second pass, wire each clone's next and random by looking up the map — the tangled random links copy perfectly.
pass 1: clone nodes, map old→new→pass 2: set next & random via map

🧬 Clone with Random Pointers II O(1) interleave

No map needed — weave each clone right after its original, copy random links, then unzip.

💡 Intuition

Weave, wire, split: insert each clone directly after its original (A → A' → B → B' …). Now a clone's random is simply orig.random.next — the clone sits right beside the target's original. Finally unzip the two lists apart.
interleave clones→clone.random = orig.random.next→split the two lists
🔒 Keep forever: "Put each clone beside its original so random = orig.random.next — no map."

📥 Flatten a Multi-Level List Merge downs

Each node has a sorted down list; flatten everything into one sorted list by merging.

💡 Intuition

Collapse the columns: each top node heads a sorted vertical list. Merge them like merging sorted lists — repeatedly merge the current flattened result with the next column's down-list. Right-to-left keeps it clean.
each column is sorted (down)→merge columns pairwise→one sorted list
🔒 Keep forever: "Flatten = repeatedly merge sorted down-lists into one."
Columns [5,7,8,30] · [10,20] · [19,22,50] · [28,35] → merged sorted.
Flattened
Press play. Merge the sorted columns together.
🐢 🐇
🧠
Never forget: merge from the last column backward, always keeping the running result sorted. Uses the two-list merge as a subroutine.
Node flatten(Node head){
  if(head==null || head.next==null) return head;
  head.next = flatten(head.next);
  return merge(head, head.next);   // merge along 'down'
}

↔️ Doubly Linked List Both directions

Each node points to both next and prev, enabling O(1) removal and backward traversal.

💡 Intuition

A two-way street: with a prev link, you can walk backward and delete a node in O(1) given only that node — just splice its neighbours together. The cost is one extra pointer per node.
node = prev · value · next·delete: prev.next=next; next.prev=prev
🔒 Keep forever: "Two links per node ⇒ walk both ways and delete in O(1)."
Doubly list 10 ⇄ 20 ⇄ 30 ⇄ 40. Insert 25, delete 20.
Doubly List
Press play. Both prev & next get rewired.
🐢 🐇
🧠
Never forget: update four pointers on insert. Doubly lists power LRU caches, deques, and browser history.
insertAfter(p, x){ Node n=new Node(x); n.prev=p; n.next=p.next;
  if(p.next!=null) p.next.prev=n; p.next=n; }
delete(n){ n.prev.next=n.next; if(n.next!=null) n.next.prev=n.prev; }

💾 LRU Cache I — HashMap + Doubly List O(1)

Evict the Least-Recently-Used item in O(1) using a hash map (for lookup) + a doubly list (for order).

💡 Intuition

A shelf of recent items: keep most-recently-used at the front of a doubly list, least-recently-used at the back. A hash map maps key → node for O(1) access. On get/put, move the node to the front; when full, drop the back node.
get/put → move node to front·full? evict the back (LRU)
🔒 Keep forever: "Map for O(1) find + doubly list for O(1) reorder = O(1) LRU."

💾 LRU Cache II — via LinkedHashMap Access order

A shortcut implementation: a LinkedHashMap in access-order maintains recency for you.

💡 Intuition

Let the library track order: a LinkedHashMap with access-order = true moves any accessed key to the end automatically. Override removeEldestEntry to drop the front when size exceeds capacity — LRU in a few lines.
accessOrder=true→get/put reorder automatically→removeEldestEntry evicts LRU
🔒 Keep forever: "LinkedHashMap(accessOrder) + removeEldestEntry = LRU for free."
