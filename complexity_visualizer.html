⏱️ Introducing Time Complexity Big-O growth

Time complexity describes how an algorithm's operation count grows with the input size n — not the wall-clock time, but the shape of the growth.

💡 Intuition

Count the steps as n grows: Big-O captures the dominant growth rate. O(1) is flat, O(log n) barely rises, O(n) is a line, O(n log n) curves up gently, O(n²) shoots up, and O(2ⁿ) explodes. Watch the curves separate as n increases — that gap is the difference between fast and unusable.
O(1)<O(log n)<O(n)<O(n log n)<O(n²)<O(2ⁿ)
🔒 Keep forever: "Big-O = how the work grows with n. Compare the growth rate, ignore machine speed."

📉 Order of Expressions & Recurrence Relations drop & solve

To find the order of growth, keep only the fastest-growing term and drop constants. For recursive algorithms, unfold the recurrence into a tree.

💡 Intuition

Only the biggest term survives: 3n² + 5n + 7 → drop the constant 7, drop the lower-order 5n, drop the coefficient 3 → O(n²). For recurrences like merge sort's T(n) = 2T(n/2) + n, each tree level costs n and there are log n levels → O(n log n).
drop constants→drop lower-order terms→recurrence → tree → sum levels
🔒 Keep forever: "Order = the dominant term without its coefficient. Recurrence = level cost × number of levels."
simplify 3n² + 5n + 7
recurrence tree: T(n) = 2·T(n/2) + n (n = 8)

🔬 Interesting Code Snippets read the loops

Most complexity comes down to counting how many times the innermost line runs. Let's analyze four telling snippets.

💡 Intuition

Count the inner line: a single loop over n → O(n); two nested loops → O(n²); a loop where the index doubles (i *= 2) → O(log n); a triangular loop (j < i) still runs ~n²/2 → O(n²) (constants dropped). Watch the operation counter for each.
single loop → O(n)·nested → O(n²)·i*=2 → O(log n)·j<i → O(n²)
🔒 Keep forever: "Complexity = how many times the innermost statement executes, as a function of n."

💾 Space Complexity memory used

Space complexity counts the extra memory an algorithm uses as a function of n — including the recursion call stack, not just explicit arrays.

💡 Intuition

Recursion costs stack frames: a few variables → O(1); an array of size n → O(n); an n×n matrix → O(n²). And recursion is sneaky: factorial(n) uses no array, yet its call stack grows to depth n before unwinding → O(n) space.
O(1): a few vars·O(n): array or stack depth n·O(n²): matrix
🔒 Keep forever: "Space = auxiliary memory incl. the recursion stack — deep recursion is O(depth) space."
