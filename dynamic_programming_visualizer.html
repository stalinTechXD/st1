🧩 What is Dynamic Programming? solve once, reuse

DP solves problems that have overlapping subproblems and optimal substructure — by solving each subproblem once and caching the answer instead of recomputing it.

💡 Intuition

Fibonacci recomputes: naive fib(n)=fib(n−1)+fib(n−2) re-solves the same calls exponentially — fib(2) appears again and again (pink nodes). Cache each result (memoize) and every subproblem is computed just once → exponential becomes linear.
overlapping subproblems+optimal substructure→solve once, cache, reuse

🔁 Top-down vs Bottom-up memoization vs tabulation

Two ways to implement DP. Top-down: recurse and cache (memoization). Bottom-up: iterate and fill a table from base cases (tabulation).

💡 Intuition

Same answers, opposite direction: top-down starts at the goal and dives down, caching as it returns. Bottom-up starts at the base cases and builds forward until it reaches the goal. Both compute each state once. Here we tabulate Fibonacci left-to-right → fib(6)=8.
top-down: recurse + memo (lazy)vsbottom-up: fill table (eager)
🔒 Keep forever: "Top-down = recursion + cache; bottom-up = iterate a table from the base cases up."
bottom-up table: dp[i] = dp[i−1] + dp[i−2]

🐢 🐇
🧠
Never forget: top-down is easier to write (just add a cache to recursion); bottom-up avoids recursion overhead & enables space optimization.

fib(n){ if(n<2)return n;   dp[0]=0; dp[1]=1;
  if(memo[n])return memo[n];   for(i=2..n) dp[i]=dp[i-1]+dp[i-2];
  return memo[n]=fib(n-1)+fib(n-2); }

🪜 Staircase (Climbing Stairs) ways to the top

How many ways to climb n stairs taking 1 or 2 steps at a time? The last move is either a 1-step or a 2-step, so dp[i] = dp[i−1] + dp[i−2].

💡 Intuition

Split by the final step: to reach stair i, you either came from i−1 (a 1-step) or i−2 (a 2-step). So the ways add up — it's Fibonacci again. Base: dp[0]=1 (one way: do nothing), dp[1]=1. For n=5 → 8 ways.
last step = 1 or 2→dp[i]=dp[i−1]+dp[i−2]→dp[n] = answer

🧱 Tile the Lane (2×n Dominoes) tiling count

How many ways to fully tile a 2×n lane with 2×1 dominoes? The last column is either one vertical tile, or two horizontals spanning the last two columns.

last col: 1 vertical → dp[n−1]·2 horizontals → dp[n−2]→sum

🏠 Maximum Non-Adjacent Sum I house robber

Pick numbers to maximize the sum, but never two adjacent ones. For each index: skip it (keep dp[i−1]) or take it (dp[i−2] + value).

💡 Intuition

Rob or skip each house: dp[i] = max(dp[i−1], dp[i−2] + a[i]). Skipping keeps the best so far; taking adds the current value to the best from two back (so no adjacency). Array [3,2,5,10,7] → 15 (3 + 5 + 7).
skip i → dp[i−1]·take i → dp[i−2]+a[i]→dp[i] = max

💡 Maximum Non-Adjacent Sum II O(1) space

The whole table isn't needed — only the previous two answers. Roll two variables forward and drop the array entirely.

Two variables suffice: keep prev (dp[i−1]) and prev2 (dp[i−2]). Each step: cur = max(prev, prev2 + a[i]), then shift prev2 = prev, prev = cur. Same answer 15, but O(1) memory instead of O(n).
cur = max(prev, prev2 + a[i])→prev2 = prev; prev = cur

🔡 Count of Decodings I A=1 … Z=26

A digit string maps to letters (1→A … 26→Z). How many ways to decode it? At each position, take one digit and/or a valid two-digit pair.

💡 Intuition

One digit or two: dp[i] = ways to decode the first i chars. Add dp[i−1] if the single digit s[i−1] is 1–9; add dp[i−2] if the two-digit s[i−2..i−1] is 10–26. String "226" → 3 ("2 2 6", "22 6", "2 26").
single 1–9 → += dp[i−1]·pair 10–26 → += dp[i−2]

🪚 Rod Cutting unbounded choices

A rod of length n and a price for each length. Cut it (or not) to maximize total price. Each length can be used any number of times.

💡 Intuition

Try every first cut: dp[len] = max over cut c of price[c] + dp[len − c]. Because a length can repeat, after cutting a piece you're free to reuse any length again (unbounded). Length 8 with prices [1,5,8,9,10,17,17,20] → 22 (cut 2 + 6).
for each length→try every first cut c→price[c] + dp[len−c]
🔒 Keep forever: "Rod cutting = unbounded knapsack: dp[len] = max(price[c] + dp[len−c]) over all cuts c."

🪙 Coin Exchange I — Minimum Coins fewest coins

Given coin denominations and a target amount, find the fewest coins that sum to it (coins reusable). dp[a] = 1 + min over coins c of dp[a − c].

💡 Intuition

Best amount minus a coin: to make amount a with the fewest coins, try each coin c: use it (1 coin) plus the best way to make a−c. Take the minimum. Unreachable amounts stay ∞. Coins {1,2,5}, amount 11 → 3 (5+5+1).
for amount a = 1..N→try each coin c→dp[a]=min(dp[a], 1+dp[a−c])
🔒 Keep forever: "Min coins: dp[a] = 1 + min(dp[a − c]) over coins c; base dp[0]=0."
dp[a] = fewest coins to make amount a (coins {1,2,5})

🔢 Coin Exchange II — Count Ways combinations

Count the number of distinct combinations of coins that make the amount (order doesn't matter). A 2D table over (coins considered × amount).

💡 Intuition

Include or exclude each coin: dp[i][a] = ways to make a using the first i coin types. Either skip coin i (dp[i−1][a]) or use it at least once (dp[i][a − coin]). Processing coins in an outer loop avoids counting permutations. Coins {1,2,5}, amount 5 → 4.
skip coin → dp[i−1][a]+use coin → dp[i][a−coin]
🔒 Keep forever: "Count ways = skip-or-use per coin: dp[i][a] = dp[i−1][a] + dp[i][a−coin]."

📊 Coin Ways — Bottom-up Tabulation fill the table

The same 2D recurrence, filled iteratively row by row from the base case dp[·][0] = 1 (one way to make 0: take nothing).

💡 Intuition

Build from empty: initialize the "amount 0" column to 1. For each coin (row) and each amount (column), add the ways without this coin (cell above) to the ways using it (cell coin steps left in the same row). The bottom-right cell is the answer → 4.
dp[·][0] = 1→row by row, left to right→dp[last][amount]

🎯 Coin Ways — Space Optimised (1D) one array

🎒 0/1 Knapsack take or leave

Each item can be taken at most once. Maximize value within a weight capacity. dp[i][w] = best value using the first i items within capacity w.

💡 Intuition

Include or exclude item i: skip it (dp[i−1][w]) or take it if it fits (value[i] + dp[i−1][w − weight[i]]) and keep the max. Because we read the previous row, each item is used at most once. Items w[1,3,4,5]/v[1,4,5,7], cap 7 → 9.
skip → dp[i−1][w]·take → v[i]+dp[i−1][w−wt[i]]→max
🔒 Keep forever: "0/1 knapsack: dp[i][w] = max(skip dp[i−1][w], take v[i]+dp[i−1][w−wt[i]])."
dp[i][w] : rows = items, cols = capacity 0..7

📦 0/1 Knapsack — Space Optimised (1D) reverse sweep

Collapse to a single array, but sweep capacities right to left so each item is used only once.

💡 Intuition

Reverse to stay 0/1: keep one array dp[0..cap]. For each item, update dp[w] = max(dp[w], value + dp[w − weight]) going right→left — this guarantees dp[w−weight] still refers to the previous item's value (not this item reused). Same answer 9, O(cap) space.
for each item→w = cap … weight (reverse)→dp[w]=max(dp[w], v+dp[w−wt])
🔒 Keep forever: "1D 0/1 knapsack sweeps capacity right→left; that reversal is what keeps each item single-use."

📈 Longest Increasing Subsequence O(n²) DP

Find the length of the longest strictly increasing subsequence. dp[i] = LIS ending at i = 1 + max(dp[j]) over all j<i with a[j]<a[i].

💡 Intuition

Best chain ending here: for each index, look back at every smaller earlier element and extend its best chain. The overall answer is the maximum dp value. Array [10,9,2,5,3,7,101,18] → 4 (e.g. 2,3,7,101).
dp[i]=1→for j<i, a[j]<a[i]: dp[i]=max(dp[i],dp[j]+1)→answer = max dp

⛰️ Longest Bitonic Subsequence up then down

🧬 Longest Common Subsequence I 2D DP

The longest subsequence present in both strings. If the current chars match, extend the diagonal; else take the best of dropping one char from either string.

💡 Intuition

Match or drop: dp[i][j] = LCS of prefixes s1[0..i), s2[0..j). If s1[i−1]==s2[j−1] → 1 + dp[i−1][j−1]; else max(dp[i−1][j], dp[i][j−1]). "abcde" & "ace" → 3 ("ace").
match → 1 + diagonal·no match → max(up, left)

🪞 Longest Palindromic Subsequence — via LCS reverse trick

The LPS of a string equals the LCS of the string with its own reverse — a palindrome reads the same forwards and backwards.

💡 Intuition

Match a string to its mirror: characters that line up in both s and reverse(s) form a palindromic subsequence. So LPS(s) = LCS(s, reverse(s)). For "bbbab", reverse "babbb", their LCS = 4 ("bbbb").
t = reverse(s)→LCS(s, t)→= LPS(s)
🔒 Keep forever: "LPS(s) = LCS(s, reverse(s)) — reuse the LCS table, no new algorithm."

🃏 Pattern Matching I — Wildcards ? and *

Match text against a pattern where ? matches any single char and * matches any sequence (including empty). 2D boolean DP.

💡 Intuition

Star = skip or absorb: dp[i][j] = does text[0..i) match pattern[0..j). On *: dp[i][j−1] (star matches empty) OR dp[i−1][j] (star absorbs one more char). On a literal or ?: dp[i−1][j−1] if chars are compatible. "adceb" vs "*a*b" → match ✓.
* → dp[i][j−1] or dp[i−1][j]·? or equal → dp[i−1][j−1]
🔒 Keep forever: "Wildcard *: match empty (left) or absorb a char (up); ? matches any single char."

🔣 Pattern Matching II — Regex . and *

Here . matches any single char and * means "zero or more of the preceding element". Subtler than wildcards.

💡 Intuition

Star binds to the char before it: for x*, either use zero copies (dp[i][j−2]) or, if the preceding pattern char matches text[i−1], consume one (dp[i−1][j]). Otherwise chars must match directly (dp[i−1][j−1]). "aab" vs "c*a*b" → match ✓.
x* → skip (dp[i][j−2])·or match & consume (dp[i−1][j])

🔟 Counting Subsequences I distinct subseq.

Count how many times string t appears as a subsequence of string s. 2D DP over prefixes.

💡 Intuition

Use it or skip it: dp[i][j] = ways t[0..j) appears in s[0..i). Always inherit dp[i−1][j] (skip s[i−1]); if s[i−1]==t[j−1], also add dp[i−1][j−1] (match this char). "rabbbit" containing "rabbit" → 3.
skip s[i−1] → dp[i−1][j]+if match → dp[i−1][j−1]
🔒 Keep forever: "Distinct subsequences: dp[i][j] = dp[i−1][j] + (match ? dp[i−1][j−1] : 0)."

#️⃣ Counting Subsequences II 1D space

The same count with a single 1D array over t, updated right→left per character of s.

💡 Intuition

One array, reverse sweep: keep dp[0..m] with dp[0]=1. For each char of s, update j from high to low: if s-char == t[j−1], dp[j] += dp[j−1]. Right→left prevents using the same s char twice within one step. Result 3.
dp[0]=1→for each s-char, j high→low→match ? dp[j]+=dp[j−1]

✖️ Matrix Chain Multiplication I interval DP

Given matrix dimensions, parenthesize the product to minimize scalar multiplications. dp[i][j] = min cost to multiply matrices i..j.

💡 Intuition

Try every split point: for chain i..j, pick a split k: cost = dp[i][k] + dp[k+1][j] + p[i−1]·p[k]·p[j] (the cost to combine the two halves). Take the min over all k. Dims [1,2,3,4] → 18.
for each chain length→try each split k→dp[i][k]+dp[k+1][j]+cost
🔒 Keep forever: "MCM: dp[i][j] = min over k of dp[i][k] + dp[k+1][j] + p[i−1]·p[k]·p[j]."
