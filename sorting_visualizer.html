⚖️ Comparators & Stability Foundation

A comparator answers one question: "should A come before B?" A sort is stable if equal elements keep their original order.

💡 Intuition

The queue at a bank: two people arrive with the same ticket number. A stable teller serves them in arrival order; an unstable one might flip them. When you sort by a second key later, stability is what preserves the first key's order.

Why it matters: multi-key sorting works by sorting on the least-important key first, then a stable sort on the next key. Without stability, earlier work is scrambled.

🔒 Keep forever: "Comparator = who goes first. Stable = ties never reorder."
Sorting [3a, 1a, 3b, 2a, 1b] by number. Watch equal keys (letters mark original order) stay a before b.
Press play to sort stably — ties keep their letters in order.
🐢 🐇
🧠
Never forget: comparator returns negative / 0 / positive for "before / tie / after". Stability preserves input order on the 0 (tie) case.
// comparator: ascending by value
cmp(a, b) => a - b;          // <0 a first, 0 tie, >0 b first
// stable multi-key: sort by minor key first, then stable-sort by major
list.sort((x,y) => x.age - y.age);      // minor
list.sort((x,y) => x.name.compareTo(y.name)); // major (stable keeps age order on ties)

🧩 Custom Comparators Rules

Sort by any rule you invent — here: by word length, breaking ties alphabetically.

💡 Intuition

The tie-breaker ladder: compare the primary key; only if it ties do you fall to the next rule. Like ranking by score, then by name, then by ID — each rung breaks the tie above it.
🔒 Keep forever: "Chain rules: return the first non-zero comparison."
Sorting [pear, fig, apple, kiwi, plum] by length, then A→Z.
Press play to sort by length, ties broken alphabetically.
🐢 🐇
🧠
Never forget: a.len - b.len first; if 0, fall through to a.compareTo(b). First non-zero wins.
words.sort((a, b) => {
  if (a.length != b.length) return a.length - b.length; // primary
  return a.compareTo(b);                                // tie-breaker
});

📥 Insertion Sort O(n²)

Build a sorted region one element at a time — like arranging playing cards in your hand.

💡 Intuition

Sorting cards in hand: pick the next card and slide it left past every bigger card until it drops into place. The left side is always sorted and grows by one each round.
take next key→shift bigger ones right→drop key in the gap
🔒 Keep forever: "Grow a sorted left side; insert each new card where it belongs."
Press play. Left region stays sorted and grows.
🐢 🐇
🧠
Never forget: best case O(n) on nearly-sorted data — that's why it's used for tiny/almost-sorted arrays. Stable.
for (int i = 1; i < n; i++) {
  int key = a[i], j = i - 1;
  while (j >= 0 && a[j] > key) { a[j+1] = a[j]; j--; } // shift right
  a[j+1] = key;                                     // drop into the gap
}

🫧 Bubble Sort O(n²)

Repeatedly swap adjacent out-of-order pairs — the largest value "bubbles" to the end each pass.

💡 Intuition

Bubbles rising: sweep left→right swapping neighbors when the left is bigger. After one sweep the biggest has floated to the top (end). Repeat on the shrinking rest.
🔒 Keep forever: "Each pass floats the next-largest to the end."
Press play. Largest bubbles to the right each pass.
🐢 🐇
🧠
Never forget: a pass with zero swaps → already sorted → stop early. Number of swaps equals the number of inversions (see below!).
for (int i = 0; i < n-1; i++) {
  boolean swapped = false;
  for (int j = 0; j < n-1-i; j++)
    if (a[j] > a[j+1]) { swap(a,j,j+1); swapped = true; }
  if (!swapped) break; // already sorted
}

➖ Dealing with Absolute Values Key trick

Sort by distance from zero — negatives and positives interleave by magnitude.

💡 Intuition

Closest to the campfire: people stand at positions like −7, +2, −3. Order them by how far they are from the fire (0), ignoring which side. The comparator just uses |value|.
🔒 Keep forever: "Change the key, not the algorithm — compare by |x|."
Sorting [-7, 2, -3, 5, -1, 4] by absolute value.
Press play to sort by |value| (closest to 0 first).
🐢 🐇
🧠
Never forget: most "sort by X" problems are just a new comparator key: |x|, x%k, frequency, distance… the sort stays the same.
a.sort((x, y) => Math.abs(x) - Math.abs(y));

🟰 Solve Equations (Sort + Two Pointers) Technique

Find a + b = target in a sorted array using two pointers from both ends.

💡 Intuition

The see-saw: put a finger on the smallest and largest. Too heavy (sum too big)? Move the right finger in. Too light? Move the left finger out. Sorting turns a messy equation into a smooth converging search.
sort→l=0, r=n-1→sum>target? r--/sum<target? l++
🔒 Keep forever: "Sort first, then let two pointers squeeze toward the answer."
Sorted [1,3,4,6,8,10,13], find a pair summing to 14.
Press play. l and r converge to the pair.
🐢 🐇
🧠
Never forget: sorting unlocks two-pointer (and binary search). Pair sum, 3-sum, closest sum — all start with a sort.
sort(a); int l=0, r=n-1;
while (l < r) {
  int s = a[l] + a[r];
  if (s == target) return {l, r};
  else if (s < target) l++; else r--;
}

🔀 Next Greater Permutation Classic

Rearrange numbers into the next larger arrangement in lexicographic order — in place.

💡 Intuition

The odometer that must tick up minimally: scan from the right to find the first "dip" (a[i] < a[i+1]) — that's the digit to bump. Swap it with the smallest number to its right that's still bigger, then reverse the tail so the suffix is as small as possible.
1. find pivot dip from right→2. swap with next-bigger successor→3. reverse the suffix
🔒 Keep forever: "Find the dip, swap with its smallest bigger, reverse the rest."
Next permutation of [1, 3, 5, 4, 2] → [1, 4, 2, 3, 5].
Press play to compute the next permutation.
🐢 🐇
🧠
Never forget: pivot = first i (from right) with a[i]<a[i+1]. No dip → array is the largest → reverse whole thing to the smallest.
int i = n-2; while (i>=0 && a[i]>=a[i+1]) i--;   // find dip
if (i>=0) {
  int j = n-1; while (a[j]<=a[i]) j--;         // smallest bigger
  swap(a,i,j);
}
reverse(a, i+1, n-1);                        // minimize suffix

📏 Maximize the Index Difference Two arrays

Find the largest j − i such that a[i] ≤ a[j] — using precomputed min/max sweeps.

💡 Intuition

Longest valid bridge: you want the widest span where the right end isn't smaller than the left. Precompute, for each i, the smallest value up to i (LMin) and for each j the largest value from j on (RMax). Then walk two pointers: if LMin[i] ≤ RMax[j], the span is valid — stretch it.
🔒 Keep forever: "Prefix-min from left, suffix-max from right, then greedily widen."
Array [34, 8, 10, 3, 2, 80, 30, 33, 1] → best span shown live.
Press play. LMin/RMax pointers widen the valid span.
🐢 🐇
🧠
Never forget: if LMin[i] ≤ RMax[j] → record j−i, advance j; else advance i. O(n) after the two sweeps.
build LMin[i] = min(a[0..i]);  build RMax[j] = max(a[j..n-1]);
int i=0, j=0, best=0;
while (i<n && j<n) {
  if (LMin[i] <= RMax[j]) { best = max(best, j-i); j++; }
  else i++;
}

🎯 Smallest Subarray to Sort Scan

Find the shortest continuous subarray that, if sorted, makes the whole array sorted.

💡 Intuition

The messy middle: scan from the left until order first breaks, and from the right until it breaks. Inside that messy window find the true min and max — then stretch the window outward until every element left of it is ≤ min and every element right is ≥ max.
find left/right break points→min & max of the dip→extend to fit them
🔒 Keep forever: "Locate the dip, then widen it until neighbors respect its min & max."
Array [2, 6, 4, 8, 10, 9, 15] → window [6,4,8,10,9].
Press play to find the shortest unsorted window.
🐢 🐇
🧠
Never forget: the answer's left edge is the first index whose value > window-min; right edge is the last index whose value < window-max.
// 1) find first l where a[l]>a[l+1], last r where a[r]<a[r-1]
// 2) mn=min(a[l..r]), mx=max(a[l..r])
while (l>0 && a[l-1]>mn) l--;   // extend left
while (r<n-1 && a[r+1]<mx) r++; // extend right
return r - l + 1;

📊 Processing Range Queries Difference Array

Apply many add v to [l..r] updates in O(1) each, then rebuild the array with one prefix-sum sweep.

💡 Intuition

Light switches on a hallway: instead of touching every bulb in a range, flip a "+v starts here" marker at l and a "−v stops here" marker at r+1. Later, walk the hallway once accumulating markers — every bulb lights to its correct total.
diff[l] += v→diff[r+1] −= v→prefix-sum = final array
🔒 Keep forever: "Mark the edges (+v at l, −v after r); one sweep pays all debts."
Base [0,0,0,0,0,0]. Queries: +5 on [1..3], +3 on [2..5], +2 on [0..1].
Press play. Mark edges, then sweep to totals.
🐢 🐇
🧠
Never forget: N range-add queries in O(N + range-count) total. The prefix-sum at the end turns edge markers into real values.
for each (l, r, v): diff[l] += v; if (r+1<n) diff[r+1] -= v;
for (int i=1; i<n; i++) diff[i] += diff[i-1]; // prefix sum = answer

🗳️ Special Election (Majority Vote) Boyer–Moore

Find the element appearing more than n/2 times — the "winner" — in O(n) time, O(1) space.

💡 Intuition

Cancelling votes: keep one candidate and a tally. A matching vote adds 1; a different vote cancels 1. Whenever the tally hits 0, the next voter becomes the new candidate. A true majority can never be fully cancelled — it survives to the end.
count==0 → adopt current as candidate→same? count++/different? count−−
🔒 Keep forever: "Pair off opposing votes; the majority is the last one standing."
Votes [2, 2, 1, 1, 1, 2, 2] → winner 2.
Press play. Candidate + count survive the cancellations.
🐢 🐇
🧠
Never forget: this only guarantees a candidate — verify with a second pass if a majority isn't guaranteed to exist.
int cand = 0, count = 0;
for (int x : a) {
  if (count == 0) cand = x;
  count += (x == cand) ? 1 : -1;
}
return cand; // majority candidate

🔗 The Merge Process Core skill

Combine two already sorted lists into one sorted list with a simple two-pointer walk.

💡 Intuition

Zipping two lines: two sorted queues face a single door. Repeatedly let the smaller head through. Since each queue is sorted, comparing only the two fronts is enough — like a zipper closing.
🔒 Keep forever: "Compare the two fronts, take the smaller, repeat."
A = [1,4,7,8], B = [2,3,9] → merged output builds below.
Press play. The smaller front always moves to output.
🐢 🐇
🧠
Never forget: O(n+m), and it's stable if you take from the left array on ties. This is the engine of merge sort.
int i=0, j=0, k=0;
while (i<n && j<m) out[k++] = (A[i] <= B[j]) ? A[i++] : B[j++];
while (i<n) out[k++] = A[i++];
while (j<m) out[k++] = B[j++];

🤝 Application of Merge (Union & Intersection) Two pointers

The merge walk instantly gives the union and intersection of two sorted arrays.

💡 Intuition

Two guest lists: walk both sorted lists together. Equal names → in both (intersection). Otherwise advance the smaller. Every name lands in the union exactly once.
🔒 Keep forever: "Same → intersection + advance both; else advance the smaller."
A = [1,3,4,6,8], B = [2,3,6,7]. Watch ∪ and ∩ form.
Press play to compute union & intersection.
🐢 🐇
🧠
Never forget: the merge two-pointer also powers "median of two sorted arrays", "kth element", and external sort.
while (i<n && j<m) {
  if (A[i]==B[j]) { both.add(A[i]); uni.add(A[i]); i++; j++; }
  else if (A[i]<B[j]) uni.add(A[i++]);
  else uni.add(B[j++]);
}

🪄 Merge Sort O(n log n)

Split until single elements, then merge sorted pieces back — shown bottom-up as widening merges.

💡 Intuition

Divide & conquer: a single element is already sorted. Merge pairs into sorted 2's, those into sorted 4's, and so on. Each level merges the whole array once → log n levels × n work.
width 1 (each sorted)→merge into 2's→4's→whole array
🔒 Keep forever: "Sorted halves + the merge zipper = a fully sorted whole, in n log n."
Press play. Watch sorted blocks double in width each level.
🐢 🐇
🧠
Never forget: guaranteed O(n log n), stable, but uses O(n) extra space for the merge buffer.
void mergeSort(a, lo, hi) {
  if (lo >= hi) return;
  int mid = (lo+hi)/2;
  mergeSort(a, lo, mid); mergeSort(a, mid+1, hi);
  merge(a, lo, mid, hi); // the zipper from above
}

🔁 Counting Inversions Merge trick

An inversion is a pair out of order (i<j but a[i]>a[j]). Count them all in O(n log n) during a merge.

💡 Intuition

Measuring messiness: inversions count how "unsorted" an array is (0 = sorted, max = reversed). While merging, if a right-side element is smaller than a left-side one, it jumps ahead of all remaining left elements — add that many inversions in one shot.
🔒 Keep forever: "When a right element wins the merge, it was smaller than every left leftover — count them all."
Array [8, 4, 2, 1] → 6 inversions (fully reversed).
Press play. Counter rises as out-of-order pairs are found.
🐢 🐇
🧠
Never forget: brute force is O(n²); the merge-sort version counts cross-inversions per merge for O(n log n).
// inside merge, when taking B[j] over A[i]:
if (A[i] <= B[j]) out[k++]=A[i++];
else { out[k++]=B[j++]; inversions += (mid - i + 1); } // all left leftovers

💡 Application of Inversions Insight

Inversion count = minimum adjacent swaps to sort — exactly the number of swaps bubble sort makes.

💡 Intuition

Untangling a line: every adjacent swap fixes exactly one out-of-order pair. So the least number of neighbor-swaps to sort an array equals its inversion count. It also measures "distance from sorted" and detects global vs local disorder.
🔒 Keep forever: "Each adjacent swap kills one inversion → min swaps = inversion count."
Bubble-sorting [3, 1, 2] (2 inversions) takes exactly 2 adjacent swaps. Watch the swap counter match.
Press play. Swap counter equals the inversion count.
🐢 🐇
🧠
Never forget: uses of inversions — min swaps, "how sorted is it", counting significant pairs, and array similarity.
minAdjacentSwaps(a) == countInversions(a);
// also: array is sortable by adjacent swaps iff you can afford that many moves

⚡ Quick Sort O(n log n) avg

Pick a pivot, partition smaller-left / bigger-right, then recurse on each side — all in place.

💡 Intuition

Sorting a bookshelf by one book: grab a pivot book; shove all shorter books left, taller right. The pivot is now in its final slot. Repeat on each side. No merge buffer needed — the swaps happen in place.
choose pivot→partition around it→recurse left & right
🔒 Keep forever: "Partition puts the pivot home; recurse on both sides."
Press play. Pink = pivot landing in its final place.
🐢 🐇
🧠
Never forget: average O(n log n), worst O(n²) on bad pivots (sorted input + naive pivot). Fix with random/median pivot. Not stable.
void quickSort(a, lo, hi) {
  if (lo >= hi) return;
  int p = partition(a, lo, hi); // pivot final index
  quickSort(a, lo, p-1); quickSort(a, p+1, hi);
}

✂️ Space-Efficient Partition O(1) space

The heart of quick sort: rearrange around a pivot in place with a single scan (Lomuto scheme).

💡 Intuition

The boundary line: keep a wall i marking "everything left is ≤ pivot". Scan with j; each time you meet a small element, push it across the wall and nudge the wall right. Finally drop the pivot onto the wall — its true home.
i = lo−1 (wall)→a[j] ≤ pivot? i++, swap(i,j)→swap pivot to i+1
🔒 Keep forever: "Maintain a wall of small elements; slide the pivot onto it."
Press play. i is the wall; pivot (last bar) lands in place.
🐢 🐇
🧠
Never forget: in place = O(1) extra space. The returned index is the pivot's final, correct position.
int partition(a, lo, hi) {
  int pivot = a[hi], i = lo - 1;
  for (int j = lo; j < hi; j++)
    if (a[j] <= pivot) { i++; swap(a, i, j); }
  swap(a, i+1, hi);
  return i+1;
}

🎯 Application of Partition (Quickselect) O(n) avg

Find the k-th smallest element without fully sorting — partition, then recurse into only one side.

💡 Intuition

Only chase the right room: after a partition the pivot sits at its final rank. If that rank equals k, done. If k is smaller, the answer is entirely on the left — ignore the right half completely (and vice-versa). Discarding a whole side each time gives O(n) average.
🔒 Keep forever: "Partition, then recurse into only the side that contains k."
Press play to find the k-th smallest (k=4).
🐢 🐇
🧠
Never forget: avg O(n) since you halve the work each step (n + n/2 + n/4 + … = 2n). Worst O(n²) — use a random pivot.
int quickselect(a, lo, hi, k) {
  int p = partition(a, lo, hi);
  if (p == k) return a[p];
  return (k < p) ? quickselect(a, lo, p-1, k)
                : quickselect(a, p+1, hi, k);
}

🪣 Counting Sort O(n + k)

No comparisons! Tally how many times each value appears, then read the tally back out in order.

💡 Intuition

Sorting coins by tallying: drop each coin into the bucket for its value. Then empty buckets left→right — the coins come out sorted. Works great when values live in a small known range.
count each value→(prefix sums for positions)→emit in order
🔒 Keep forever: "Count, then pour the buckets out in order — no comparisons."
Sorting [4,2,2,8,3,3,1] (values 1–8) by tallying into buckets.
Press play. Fill buckets, then read them out sorted.
🐢 🐇
🧠
Never forget: linear when k (value range) is small. Beats the O(n log n) comparison lower bound by not comparing. Stable with prefix sums.
for (int x : a) count[x]++;              // tally
int idx = 0;
for (int v = 0; v <= maxVal; v++)
  while (count[v]-- > 0) out[idx++] = v; // pour out

🔢 Radix Sort O(d·(n+k))

Sort numbers digit by digit — least-significant first — using a stable counting sort each pass.

💡 Intuition

Sorting mail by ZIP digits: first bucket by the last digit, gather, then by the tens digit, gather, then hundreds… Because each pass is stable, earlier-digit order is preserved. After the top digit, everything is sorted.
sort by 1's digit→10's digit→100's digit
🔒 Keep forever: "Stable-sort digit by digit, least significant first — order compounds."
Sorting [170,45,75,90,802,24,2,66] one digit at a time.
Press play. Watch each digit pass reorder stably.
🐢 🐇
🧠
Never forget: stability of each digit pass is essential — it's what keeps earlier digits' order intact.
for (int exp = 1; maxVal/exp > 0; exp *= 10)
  countingSortByDigit(a, exp); // stable, on digit (x/exp)%10

🚀 Sorting in Linear Time Beyond n log n

Comparison sorts can't beat O(n log n) — but counting, radix, and bucket sort dodge comparisons entirely.

💡 Intuition

Scatter & gather: spread values across buckets by range, sort each tiny bucket, then concatenate. When values are uniformly spread, buckets stay small → linear overall. Bucket sort is the idea behind sorting floats/decimals fast.
🔒 Keep forever: "If you can bucket by value/digit, you can sort without comparing — in linear time."
Bucket-sorting decimals [.42, .32, .75, .12, .68, .23] into 6 range-buckets.
Press play. Scatter into buckets, sort each, gather.
🐢 🐇
Comparison sorts: Ω(n log n) lower bound Counting / Radix / Bucket: O(n) when range/digits are small
🧠
Never forget: linear-time sorts trade generality for speed — they need extra assumptions (small integer range, fixed digits, or uniform spread).
for (double x : a) buckets[(int)(n*x)].add(x); // scatter
for (bucket b : buckets) insertionSort(b);          // tiny sorts
concatenate(buckets);                                // gather sorted
