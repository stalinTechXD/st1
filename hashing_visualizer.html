#️⃣ What is Hashing? Foundation

A hash function turns a key into an array index, so you can store & find it in O(1) — no scanning.

💡 Intuition

Cloakroom tickets: instead of searching every coat, a formula (hash(key)) tells you exactly which peg holds it. Store there, fetch from there — constant time, no matter how many coats.
index = hash(key) % size→store at that bucket→look up in O(1)
🔒 Keep forever: "A hash function is a shortcut from key → slot. No search, just compute the address."
Insert keys [23, 45, 12, 8, 91] into a size-7 table: index = key % 7.
Press play to hash each key into its bucket.
🐢 🐇
🧠
Never forget: lookup = compute hash → jump to bucket → O(1) average. The whole point is avoiding a linear scan.
int index = hash(key) % capacity;   // key → slot
table[index] = value;                // store
value = table[hash(key) % capacity]; // O(1) fetch

🔗 How Hashtables Work — Collisions & Chaining Internals

When two keys hash to the same bucket, we chain them in a list so nothing is lost.

💡 Intuition

Shared pegs: if two coats map to the same peg, hang them on the same hook as a little chain. Lookups walk that short chain. Keep chains short (low load factor) by resizing, and average lookup stays O(1).
collision → same bucket→append to that bucket's chain→resize when too full
🔒 Keep forever: "Collisions are normal — chain them; keep the load factor low to stay O(1)."
Insert [10, 15, 20, 7, 12] into size-5 table (index = key % 5). Watch chains grow.
Press play. Keys colliding pile into the same bucket.
🐢 🐇
🧠
Never forget: worst case (all collide) is O(n); good hash + resizing keeps it O(1) average. Load factor = entries / buckets.
bucket = table[hash(key) % capacity];
bucket.add(key);            // chaining on collision
if (size / capacity > 0.75) resize(); // keep chains short

🌳 Using HashMaps & TreeMaps Choose wisely

HashMap: O(1), unordered. TreeMap: O(log n), always sorted — enabling floor/ceiling & range queries.

💡 Intuition

Pile vs bookshelf: a HashMap is a labelled pile — instant grab, no order. A TreeMap is an alphabetized shelf — a bit slower, but you can ask "what's just below 25?" (floor) or "just above?" (ceiling). Order costs a log, but unlocks range powers.
need speed, no order → HashMap·need sorted / floor / ceiling → TreeMap
🔒 Keep forever: "HashMap for O(1) lookup; TreeMap when you need order, floor, ceiling, or ranges."
Insert [50, 20, 80, 10, 30]. TreeMap keeps them sorted; then floor(25) & ceiling(25).

📊 Processing Queries (Frequency Map) Streaming

A hashmap of counts answers add / remove / "how many?" queries in O(1) each.

💡 Intuition

A running tally sheet: keep a count next to each value. Add → bump the count; remove → drop it; ask "how many 5s?" → read the count instantly. No re-scanning the data each query.
🔒 Keep forever: "Maintain counts in a map; every add/remove/query is O(1)."
Query stream: add 5, add 5, add 3, count 5, remove 5, add 7, distinct?
counts:
Press play to process the query stream.
🐢 🐇
🧠
Never forget: map size = distinct count. Frequency maps power "top-K", "first unique", "anagrams", and window problems.
count.merge(x, 1, Integer::sum);          // add
if (count.merge(x, -1, Integer::sum) == 0) count.remove(x); // remove
count.getOrDefault(x, 0);              // query

Looking for your other half: as you meet each number, check the "seen" set for target − x. If it's there, you found the pair; if not, remember x and move on.

📦 Subarray with Given Sum Prefix + Hash

Find a contiguous subarray summing to K — even with negatives — via prefix sums in a hashmap.

💡 Intuition

Mile markers: track the running total. A stretch sums to K whenever a previous total equals current − K — the road between those two markers is exactly K.
🔒 Keep forever: "Subarray = difference of two prefix sums; hash the sums you've seen."
Array [10, 2, -2, -20, 10], K = -10.
prefix→idx:
Press play. Running total meets a seen (prefix − K).
🐢 🐇
🧠
Never forget: seed with {0 → −1}. Sliding window only works for all-positive arrays; prefix+hash handles negatives.
map.put(0, -1); int pre=0;
for (int i=0; i<n; i++){ pre+=a[i];
  if (map.containsKey(pre-K)) return {map.get(pre-K)+1, i};
  map.putIfAbsent(pre, i); }

📏 Longest Subarray with Given Sum First-occurrence hash

Maximize length by storing only the earliest index of each prefix sum.

💡 Intuition

Reach back as far as possible: for the longest stretch, when you need a prefix, you want its earliest occurrence. So never overwrite a prefix already in the map — the first index gives the widest subarray.
🔒 Keep forever: "Store the FIRST index of each prefix — earliest match = longest subarray."
Array [1, -1, 5, -2, 3], K = 3 → longest length 4.
prefix→first idx:
Press play to find the longest subarray summing to 3.
🐢 🐇
🧠
Never forget: use putIfAbsent — keeping the first index is the whole trick for maximizing length.
map.put(0, -1); int pre=0, best=0;
for (int i=0; i<n; i++){ pre+=a[i];
  if (map.containsKey(pre-K)) best=max(best, i-map.get(pre-K));
  map.putIfAbsent(pre, i); }

🔢 Count of Subarrays with Sum K Prefix counts

Count all subarrays summing to K by hashing how many times each prefix sum occurred.

💡 Intuition

Every earlier match counts: at each index, every previous prefix equal to current − K starts a valid subarray. So store the count of each prefix sum and add it in — not just whether it exists.
🔒 Keep forever: "Count subarrays = sum of frequencies of (prefix − K) seen so far."
Array [1, 2, 3], K = 3 → 2 subarrays ([1,2] and [3]).
prefix→count:
Press play to count subarrays summing to 3.
🐢 🐇
🧠
Never forget: store counts (not indices), seed {0:1}, and add map[pre−K] to the answer each step.
map.put(0, 1); int pre=0, count=0;
for (int x : a){ pre+=x; count += map.getOrDefault(pre-K, 0);
  map.merge(pre, 1, Integer::sum); }

🔀 Consecutive Elements Check Hash set

Do the numbers form one unbroken run (like 2,3,4,5,6)? A set answers it in O(n).

💡 Intuition

A complete staircase: dump everything in a set, find the min and max. If they're all distinct and max − min + 1 == n, no step is missing — it's a perfect consecutive run.
🔒 Keep forever: "All distinct + (max − min + 1 == n) ⇒ consecutive."
Array [5, 3, 4, 6, 2] → consecutive? (min 2, max 6).
Press play to check for a consecutive run.
🐢 🐇
🧠
Never forget: the set also guards against duplicates — a repeat breaks "all distinct" and fails the run.
int mn=min(a), mx=max(a);
if (mx - mn + 1 != n) return false;
for (v in mn..mx) if (!set.contains(v)) return false;
return true;

🧵 Longest Consecutive Sequence O(n)

Find the longest run of consecutive integers — only start counting from run beginnings.

💡 Intuition

Only start at the bottom step: put all numbers in a set. A number begins a run only if x−1 is absent. From each true start, walk x+1, x+2, … The "start-only" rule means every number is visited once → O(n), no sorting.
no x−1? it's a start→extend x+1, x+2 …→track longest
🔒 Keep forever: "Count runs only from their start (no x−1) — each number touched once."
Array [100, 4, 200, 1, 3, 2] → longest run [1,2,3,4] = 4.
Press play. Runs grow only from their starting number.
🐢 🐇
🧠
Never forget: the "start-only" check is what makes it O(n); without it you'd re-walk runs and hit O(n²).
for (int x : set)
  if (!set.contains(x-1)) {          // start of a run
    int len=1, cur=x;
    while (set.contains(cur+1)){ cur++; len++; }
    best = max(best, len);
  }

⚡ Longest Consecutive II (Streaming) Boundary merge

Numbers arrive one at a time — merge runs on the fly by tracking each run's length at its ends.

💡 Intuition

Bridging islands: a HashMap stores the length of the run ending/starting at each boundary value. When x arrives, look left (x−1) and right (x+1): join their runs through x, then update only the two new endpoints. No re-scan — pure streaming.
left = len[x−1]·right = len[x+1]→newLen = left+right+1→update both ends
🔒 Keep forever: "Store run length at boundaries; a new number bridges left & right runs instantly."
Stream [1, 3, 2, 5, 4] → grows to one run of length 5.
value→runLen:
Press play. Each arrival merges neighbouring runs.
🐢 🐇
🧠
Never forget: only the two endpoints of a run need correct values — the interior is never queried again.
int left=len.getOrDefault(x-1,0), right=len.getOrDefault(x+1,0);
int cur=left+right+1;
len.put(x, cur);
len.put(x-left, cur); len.put(x+right, cur); // new endpoints
best=max(best, cur);

▦ Boolean Matrix (Set Zeroes) Row/Col sets

If a cell is 0, zero out its whole row and column — record which rows/cols first, then apply.

💡 Intuition

Mark then wipe: if you zero as you scan, one zero triggers a cascade of false zeros. So first note every row and column that contains a 0 (in two sets), then wipe them all at once.
scan → record zero rows & cols→then zero those rows & cols
🔒 Keep forever: "Record first, mutate later — never let a fresh zero cause new zeros."
4×4 grid with two zeros. Watch their rows & columns get wiped.
Press play. Find zeros, record rows/cols, then wipe.
🐢 🐇
🧠
Never forget: the two-set approach uses O(rows+cols) extra space. The next section shrinks that to O(1).
Set rows, cols;
for (i,j) if (m[i][j]==0){ rows.add(i); cols.add(j); }
for (i,j) if (rows.has(i) || cols.has(j)) m[i][j]=0;

▩ Boolean Matrix II (O(1) Space) In-place markers

Same task, but use the matrix's own first row & column as the record — no extra sets.

💡 Intuition

Notes in the margins: instead of separate sets, stamp a 0 into the first cell of that row and column. The margins now remember which rows/cols to wipe. Handle the first row/col with two flags, then apply — O(1) extra space.
mark zeros into row 0 & col 0→wipe body using markers→fix row 0 & col 0
🔒 Keep forever: "Reuse the first row/column as the marker board — record in place, no extra memory."
Same 4×4 grid — now the first row & column store the flags (cyan markers).
Press play. Mark in the margins, then wipe the body.
🐢 🐇
🧠
Never forget: track the first row & first column separately (they'd otherwise be corrupted), then process the interior before them.
// use m[i][0] and m[0][j] as the "sets"
for (i,j in body) if (m[i][j]==0){ m[i][0]=0; m[0][j]=0; }
for (i,j in body) if (m[i][0]==0 || m[0][j]==0) m[i][j]=0;
// then handle row 0 & col 0 via saved flags

📐 Maximum Points on a Line Slope hashing

Fix a point, hash the slope to every other point — the biggest slope group is the longest line.

💡 Intuition

Same direction, same line: from an anchor point, any two other points on the same line share the exact same slope. Group all points by their slope to the anchor; the largest group (+ the anchor) is the most collinear points through it.
for each anchor→slope to every other point→hash slopes, take max group
🔒 Keep forever: "Points on a line share a slope to any anchor — hash slopes, count the biggest bucket."
Points (0,0),(1,1),(2,2),(3,1),(1,0) → line y=x holds 3 points.
slope→count:
Press play. Anchor at (0,0); group points by slope.
🐢 🐇
🧠
Never forget: use a reduced fraction (dy/gcd, dx/gcd) as the slope key to avoid float errors. Overall O(n²).
for anchor i:
  map.clear();
  for j != i: map[slope(i,j)]++;
  best = max(best, max(map.values()) + 1); // +1 for anchor

Find start indices where a substring is exactly all the words joined in some order.

🔁 Making Palindromes (Rearrangeable?) Char frequency

Can a string's letters be rearranged into a palindrome? Count how many letters appear an odd number of times.

💡 Intuition

Mirror pairs + one center: a palindrome mirrors around its middle, so every letter must appear an even number of times — except at most one that sits in the exact center. Count odd frequencies: 0 or 1 → yes, more → no.
🔒 Keep forever: "At most one odd count ⇒ a palindrome permutation exists."
s = "aabbc" → freq a:2, b:2, c:1 → one odd → YES.
char→count:
Press play. Build frequencies, count odd ones.
🐢 🐇
🧠
Never forget: even-length strings need zero odd counts; odd-length allows exactly one (the center).
Map freq = counts(s);
int odd = 0;
for (c : freq.values()) if (c % 2 == 1) odd++;
return odd <= 1;

🔂 Making Palindrome II (Longest Buildable) Counts → length

What's the longest palindrome you can build from the letters? Use pairs, plus one odd center.

💡 Intuition

Spend letters in pairs: each letter contributes as many mirror pairs as it can (count/2 × 2). If any letter has a leftover, you may place one single letter in the very center — a free +1.
sum floor(count/2)×2→+1 if any odd count exists
🔒 Keep forever: "Longest palindrome = all pairs, plus one odd letter as the center."
s = "abccccdd" → freq c:4, d:2, a:1, b:1 → length 7.
char→count:
Press play. Add pairs, then one center if possible.
🐢 🐇
🧠
Never forget: add (count/2)*2 for every letter; add 1 at the end if any letter had an odd count.
int len=0; boolean odd=false;
for (c : freq.values()){ len += (c/2)*2; if (c%2==1) odd=true; }
return len + (odd ? 1 : 0);
