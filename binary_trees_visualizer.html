🌳 What are Trees? Foundation

A hierarchy of nodes: one root at top, each node has up to two children (in a binary tree), and childless nodes are leaves.

💡 Intuition

A family tree: the root is the ancestor, each node has descendants (children), and the ends of the lineage (no children) are leaves. There are no cycles — one path from the root to any node.
root = top·children = left & right·leaf = no children
🔒 Keep forever: "Root at top, branches down, leaves at the ends — no cycles."

🧠
Never forget: most tree algorithms are recursion — solve for a node using its children's answers. Base case: null (empty) subtree.

🔢 Counting Nodes DFS

Count every node = 1 (self) + count(left) + count(right).

💡 Intuition

Delegate and add: ask the left subtree how many nodes it has, ask the right, add 1 for yourself. An empty subtree reports 0. The counts bubble up to the root.
🔒 Keep forever: "count(node) = 1 + count(left) + count(right); count(null) = 0."
Press play to count all nodes.
🐢 🐇
🧠
Never forget: O(n) — every node visited once. The 1+left+right shape is the template for size, sum, and height.
int count(Node n){ return n==null? 0 : 1 + count(n.left) + count(n.right); }

🍃 Counting Leaves DFS

A leaf has no children — count nodes where both left and right are null.

💡 Intuition

Tips of the branches: recurse down; when you reach a node with no children, that's one leaf. Internal nodes just sum their subtrees' leaf counts.
🔒 Keep forever: "Leaf = no children → count 1; else leaves(left) + leaves(right)."
Press play to count the leaves.
🐢 🐇
🧠
Never forget: the base "leaf" check left==null && right==null also underpins root-to-leaf paths and min-height.
int leaves(Node n){
  if(n==null) return 0;
  if(n.left==null && n.right==null) return 1;
  return leaves(n.left) + leaves(n.right);
}

🪞 Mirror Image of a Binary Tree Swap

Flip the tree left-to-right by swapping every node's two children.

💡 Intuition

Reflect in a mirror: at each node, swap its left and right subtrees, then recurse into both. The whole tree flips horizontally — left becomes right all the way down.
🔒 Keep forever: "Swap children at every node → the tree mirrors."
Press play to mirror the tree.
🐢 🐇
🧠
Never forget: in-place swap of pointers, O(n). Mirroring is the core of the symmetric-tree check below.
void mirror(Node n){
  if(n==null) return;
  Node t=n.left; n.left=n.right; n.right=t;   // swap
  mirror(n.left); mirror(n.right);
}

⚖️ Symmetric Binary Tree Mirror check

Is the tree a mirror of itself? Compare the left subtree against the right subtree, flipped.

💡 Intuition

Fold it down the middle: the tree is symmetric if the left and right subtrees mirror each other — left.left matches right.right, and left.right matches right.left, all the way down.
compare (L, R)→L.left ↔ R.right·L.right ↔ R.left
🔒 Keep forever: "Symmetric = left subtree is the mirror of the right subtree."
Press play to check symmetry via mirrored pairs.
🐢 🐇
🧠
Never forget: compare two nodes at once: values equal AND (L.left,R.right) AND (L.right,R.left) all symmetric.
boolean mirror(Node a, Node b){
  if(a==null && b==null) return true;
  if(a==null || b==null || a.val!=b.val) return false;
  return mirror(a.left,b.right) && mirror(a.right,b.left);
}

📏 Height of a Binary Tree Post-order

Height = the longest path down = 1 + max(height(left), height(right)).

💡 Intuition

Tallest child wins: a node's height is one more than its taller subtree. Heights compute bottom-up — leaves are height 1, and each parent adds a level above its tallest child.
🔒 Keep forever: "height(node) = 1 + max(height(left), height(right)); height(null) = 0."
Press play. Heights bubble up (labels show each node's height).
🐢 🐇
🧠
Never forget: some define height in edges (null=−1, leaf=0). Here we count levels (null=0, leaf=1). Be consistent!
int height(Node n){ return n==null? 0 : 1 + Math.max(height(n.left), height(n.right)); }

📐 Minimum Height (Min Depth) Careful base case

The shallowest root-to-leaf path — but a node with one child isn't a leaf, so take the non-null side.

💡 Intuition

The nearest exit: min depth is the shortest path to a leaf. Watch out: if a node has only one child, you must go down that child — you can't stop at a "missing" side. Only true leaves end a path.
leaf? depth = 1·one child? go that way·two? take the min
🔒 Keep forever: "Min depth stops only at real leaves — skip a null side when the other exists."
Press play to find the shallowest leaf.
🐢 🐇
🧠
Never forget: the classic bug — returning 1+min(left,right) gives 1 for a one-child node. Guard against a null child.
int minDepth(Node n){
  if(n==null) return 0;
  if(n.left==null) return 1+minDepth(n.right);
  if(n.right==null) return 1+minDepth(n.left);
  return 1+Math.min(minDepth(n.left), minDepth(n.right));
}

🛤️ Root-to-Leaf Paths Backtracking

Enumerate every path from the root down to a leaf.

💡 Intuition

Breadcrumbs down each branch: as DFS descends, append the current node to a running path. When you hit a leaf, record the whole path; then backtrack (pop) as you return, freeing the slot for the next branch.
append node to path→leaf? record path→recurse, then pop (backtrack)
🔒 Keep forever: "Add on the way down, record at leaves, remove on the way back up."
Press play to trace every root-to-leaf path.
🐢 🐇
🧠
Never forget: backtracking = the pop after recursion. Forgetting it leaks nodes from one branch into another's path.
void dfs(Node n, List path){
  if(n==null) return;
  path.add(n.val);
  if(n.left==null && n.right==null) result.add(copy(path));
  else { dfs(n.left,path); dfs(n.right,path); }
  path.removeLast();   // backtrack
}

📊 Diameter of a Tree I — Naive O(n²)

Diameter = longest path between any two nodes. Naively: for each node, height(left)+height(right).

💡 Intuition

Try every hinge: the longest path bends at some node — going down its left as far as possible and its right as far as possible. So at each node compute height(left)+height(right) and take the max. Recomputing heights everywhere makes it O(n²).
🔒 Keep forever: "Diameter through a node = height(left)+height(right); try all nodes."
Press play. Each node tests height(left)+height(right).
🐢 🐇
🧠
Never forget: diameter in edges = maxₙ (height(left)+height(right)). O(n²) because height() is recomputed per node.
int diameter(Node n){
  if(n==null) return 0;
  int through = height(n.left) + height(n.right);
  return max(through, diameter(n.left), diameter(n.right));
}

⚡ Diameter II — Global Variable O(n)

One DFS: return each node's height while updating a global best diameter along the way.

💡 Intuition

Measure while you climb: a single post-order pass computes each node's height. At every node, the path bending through it is leftHeight + rightHeight — update a shared max. No recomputation → O(n).
🔒 Keep forever: "Compute height once; update the global diameter at each node with left+right."
Press play. Heights compute once; diameter path glows.
🐢 🐇
🧠
Never forget: the DFS returns height but side-effects the diameter. One traversal, O(n) time.
int best = 0;
int dfs(Node n){
  if(n==null) return 0;
  int l=dfs(n.left), r=dfs(n.right);
  best = max(best, l + r);       // path through n
  return 1 + max(l, r);       // height
}

✨ Diameter III — Return a Pair No globals

Cleanest version: each call returns both the height and the diameter as a pair.

💡 Intuition

Carry two answers up: avoid the shared variable by returning (height, diameter) from every node. A node's diameter is the max of its children's diameters and the path bending through it. Pure functional, no side effects.
🔒 Keep forever: "Return (height, diameter) together — no global state needed."
Press play. Each node returns (height, diameter).
🐢 🐇
🧠
Never forget: returning a small struct/pair is the clean way to avoid globals in tree DFS — reusable everywhere.
int[] dfs(Node n){   // {height, diameter}
  if(n==null) return new int[]{0,0};
  int[] L=dfs(n.left), R=dfs(n.right);
  int h = 1+max(L[0],R[0]);
  int d = max(L[1], R[1], L[0]+R[0]);
  return new int[]{h, d};
}

⚖️ Height-Balanced Check O(n)

A tree is balanced if every node's two subtree heights differ by at most 1.

💡 Intuition

No lopsided nodes: compute heights bottom-up; at each node check |leftH − rightH| ≤ 1. Return a sentinel (like −1) up the chain the moment any node fails — that short-circuits to O(n).
🔒 Keep forever: "Balanced = every node's subtree heights differ by ≤ 1; bubble a fail flag up."
Press play. Check every node's height difference.
🐢 🐇
🧠
Never forget: compute height and balance in one pass — return −1 as "unbalanced" to avoid the naive O(n²) recheck.
int check(Node n){   // height, or -1 if unbalanced
  if(n==null) return 0;
  int l=check(n.left); if(l==-1) return -1;
  int r=check(n.right); if(r==-1) return -1;
  if(Math.abs(l-r)>1) return -1;
  return 1+Math.max(l,r);
}

💰 Maximum Path Sum Any node to any node

Find the largest-sum path anywhere in the tree (it may bend through a node, not touch the root).

💡 Intuition

Best route with a peak: each node returns the best downward gain it can contribute (itself + its better child, or 0 if negative). Meanwhile, the best path through a node is node + leftGain + rightGain — update a global max with that.
gain(n) = n.val + max(0, best child)·through = n.val + leftGain + rightGain
🔒 Keep forever: "Return one-sided gain up; update the answer with the two-sided path through each node."
Press play. The maximum-sum path glows.
🐢 🐇
🧠
Never forget: clamp negative child gains to 0 (skip them). The path you return can only use one child; the path you record may use both.
int gain(Node n){
  if(n==null) return 0;
  int l=max(0,gain(n.left)), r=max(0,gain(n.right));
  best = max(best, n.val + l + r);   // path through n
  return n.val + max(l, r);         // one-sided gain
}

🔗 Binary Tree → Doubly Linked List In-order

Convert a tree into a sorted doubly linked list using an in-order traversal.

💡 Intuition

Straighten the tree: an in-order walk visits nodes in sorted order (for a BST). As you visit each node, link it after the previously visited one — prev.right = cur, cur.left = prev. The tree unrolls into a doubly linked list.
in-order: left, node, right→link cur ⇄ prev→advance prev
🔒 Keep forever: "In-order visit + link each node to the previous = a sorted doubly list."
Press play. In-order order becomes a doubly linked list.
🐢 🐇
🧠
Never forget: keep a prev pointer across the recursion. The head is the leftmost (smallest) node.
Node prev=null, head=null;
void inorder(Node n){
  if(n==null) return; inorder(n.left);
  if(prev==null) head=n; else { prev.right=n; n.left=prev; }
  prev=n; inorder(n.right);
}

🌲 All Possible Binary Trees I — Count Catalan DP

How many structurally unique BSTs hold values 1..n? The answer is the n-th Catalan number.

💡 Intuition

Pick a root, split the rest: for n nodes, any value can be the root; the smaller values form the left subtree, the larger the right. Total = Σ (ways for left) × (ways for right). This recurrence is the Catalan number.
C[0]=1→C[n] = Σ C[i]·C[n−1−i]→C[3]=5, C[4]=14…
🔒 Keep forever: "Choose a root, multiply left × right ways, sum over all roots = Catalan."
Building C[0..4]: 1, 1, 2, 5, 14.
Press play to build the Catalan DP table.
🐢 🐇
🧠
Never forget: Catalan Cₙ = (2n)! / ((n+1)! n!). It counts BSTs, balanced parentheses, triangulations, and more.
C[0]=1;
for(int n=1;n<=N;n++)
  for(int i=0;i<n;i++) C[n] += C[i]*C[n-1-i];

🌲 All Possible Binary Trees II — Generate n=3 shapes

Actually build every unique BST for values 1, 2, 3 — there are exactly 5.

💡 Intuition

Enumerate every root: for each value as root, recursively generate all left subtrees (smaller values) and all right subtrees (larger values), then combine every left with every right. For 1..3 this yields the 5 distinct shapes.
🔒 Keep forever: "Fix each root, cross-product all left shapes with all right shapes."
The 5 unique BSTs of {1, 2, 3}.
Press play to reveal all 5 BST structures.
🐢 🐇
🧠
Never forget: the count matches Catalan C₃ = 5. Generation = recursion returning a list of roots for each range.
List<Node> gen(int lo, int hi){
  if(lo>hi) return [null];
  for(int r=lo;r<=hi;r++)
    for(L : gen(lo,r-1)) for(R : gen(r+1,hi))
      add(new Node(r,L,R));
}

🌲 All Possible Binary Trees III — Full Trees Odd n DP

Full binary trees (every node has 0 or 2 children) exist only for odd node counts — count them with DP.

💡 Intuition

Split the odd remainder: a full tree's root always has two subtrees, each itself a full tree with an odd number of nodes. So F[n] = Σ F[i]·F[n−1−i] over odd splits. Even n → 0 (impossible).
F[1]=1→odd n: F[n]=Σ F[i]·F[n−1−i]→F[7]=5
🔒 Keep forever: "Full binary trees need odd n; split into two odd full subtrees."
Counting full binary trees: F[1..7] = 1, 0, 1, 0, 2, 0, 5.
Press play to count full binary trees by node count.
🐢 🐇
🧠
Never forget: even node counts can't form a full binary tree (the root's two odd subtrees + 1 is always odd).
F[1]=1;
for(int n=3;n<=N;n+=2)
  for(int i=1;i<n;i+=2) F[n] += F[i]*F[n-1-i];

🔁 Recursive Tree Traversal Pre · In · Post

The three DFS orders differ only in when you visit the node relative to its children.

💡 Intuition

Node before, between, or after: Preorder = node, then left, then right. Inorder = left, node, right (sorted for a BST). Postorder = left, right, then node (children before parent). Same recursion, one line moved.
Pre: N L R·In: L N R·Post: L R N
🔒 Keep forever: "Preorder visits the node first, inorder in the middle, postorder last."
Press play to see preorder, inorder, and postorder.
🐢 🐇
🧠
Never forget: inorder of a BST is sorted. Postorder is used to delete/free a tree (children first).
void pre(n){ if(n==null)return; visit(n); pre(n.left); pre(n.right); }
void in(n){ if(n==null)return; in(n.left); visit(n); in(n.right); }
void post(n){ if(n==null)return; post(n.left); post(n.right); visit(n); }

📚 Iterative Preorder (Stack) No recursion

Simulate the call stack explicitly: pop a node, output it, push right then left.

💡 Intuition

Be your own recursion: a stack replaces the call stack. Pop a node, visit it, then push its right child before its left — so the left is processed first (LIFO). Preorder falls right out.
pop → visit→push right→push left
🔒 Keep forever: "Stack, pop-visit, push right then left → preorder."

🎛️ A Generic Traversal Technique One stack, all orders

A single stack with a per-node visit counter yields pre, in, AND post order at once.

💡 Intuition

Three touches per node: each node is touched three times as the stack unwinds. On the 1st touch add it to preorder, on the 2nd to inorder, on the 3rd to postorder. One traversal, all three orders — the unifying view of DFS.
touch 1 → preorder·touch 2 → inorder·touch 3 → postorder
🔒 Keep forever: "Every node is touched 3 times — 1st=pre, 2nd=in, 3rd=post."
Press play. Watch all three orders fill from one traversal.
🐢 🐇
🧠
Never forget: push (node, count). On each pop, increment; emit to the matching order; re-push if count < 3, then descend. Elegant & unified.
st.push([root, 0]);
while(!st.isEmpty()){ var top=st.peek(); top[1]++;
  if(top[1]==1){ pre.add(top[0]); if(left) st.push([left,0]); }
  else if(top[1]==2){ in.add(top[0]); if(right) st.push([right,0]); }
  else { post.add(top[0]); st.pop(); }
}

push all lefts→pop & visit→go right, repeat

🌊 Level Order Traversal BFS · queue

Visit the tree level by level using a queue — breadth-first.

💡 Intuition

Ripples outward: enqueue the root; repeatedly dequeue a node, visit it, and enqueue its children. Processing the queue in FIFO order finishes each level before starting the next.
🔒 Keep forever: "A queue walks the tree level by level — that's BFS."

🧱 Vertical Order Traversal By column

Group nodes by horizontal distance (column): root = 0, left = −1, right = +1.

💡 Intuition

Drop into columns: assign each node a horizontal distance (hd) — go left subtract 1, go right add 1. BFS while tracking hd, bucketing nodes by column. Read columns left to right, top to bottom.
hd(root)=0·left → hd−1·right → hd+1·group by hd
🔒 Keep forever: "Track hd (left −1, right +1); bucket nodes into columns."
Press play to group nodes into vertical columns.
🐢 🐇
🧠
Never forget: BFS (not DFS) so nodes within a column come out top-to-bottom. Use a TreeMap keyed by hd to keep columns sorted.

while(!q.isEmpty()){ [n,hd]=q.poll(); map[hd].add(n.val);
  q.offer([n.left,hd-1]); q.offer([n.right,hd+1]); }

The top view is the first node seen in each column (from above); the bottom view is the last.

💡 Intuition

Look down / look up: using horizontal distance columns, the top view keeps only the first node BFS reaches in each column; the bottom view keeps the last (deepest) node in each column.

⚡ Count Nodes in a Complete Tree II O(log² n)

Use the complete-tree shape: if left height == right height, the subtree is perfect → 2ʰ − 1 instantly.

💡 Intuition

Perfect shortcut: walk the leftmost and rightmost paths. If they're the same length, the subtree is a perfect tree and holds exactly 2ʰ − 1 nodes — no recursion needed. Otherwise recurse into both children; only one side keeps recursing deeply.
leftH == rightH? perfect → 2ʰ−1/else 1 + count(L) + count(R)
🔒 Keep forever: "Equal left/right heights = perfect subtree = 2ʰ−1; else recurse."
Press play. Perfect subtrees are counted instantly.
🐢 🐇
🧠
Never forget: O(log n) height checks × O(log n) recursion depth = O(log² n). Much faster than O(n) on huge trees.
int count(Node n){
  int lh=leftHeight(n), rh=rightHeight(n);
  if(lh==rh) return (1<<lh)-1;      // perfect
  return 1+count(n.left)+count(n.right);
}

✨ Count Nodes in a Complete Tree III Binary search

Binary-search the last level: how many of its leftmost slots are actually filled?

💡 Intuition

Search the final row: all levels above the last are full (2ʰ⁻¹ − 1 nodes). The last level fills left to right, so binary-search which leftmost positions exist — each candidate is checked by following its path bits from the root.
upper levels full→binary search last-level slots→total = full + filled
🔒 Keep forever: "Upper levels are full; binary-search the last level's filled slots."
Press play to binary-search the last level.
🐢 🐇
🧠
Never forget: each existence check walks a root-to-leaf path (O(log n)) using the index's bits; binary search over 2ʰ⁻¹ slots → O(log² n).
// path bits of index decide left(0)/right(1) at each level
boolean exists(idx, h, root){ for bit high→low: node = (bit? node.right : node.left); return node!=null; }

🧩 Binary Tree Reconstruction Why two orders?

A single traversal is ambiguous — but two complementary traversals pin down a unique tree.

💡 Intuition

Root + split: preorder tells you the root (it comes first); inorder tells you which nodes are on the left vs right of that root (they sit before/after it). Recurse on each side. Two views together remove all ambiguity.
root = preorder[0]→find root in inorder→split into left / right
🔒 Keep forever: "Preorder gives the root; inorder splits left from right."
preorder = [1,2,4,5,7,3,6] · inorder = [4,2,7,5,1,3,6]

root = preorder[0]; i = indexOf(root, inorder);
left  = build(inorder[0..i]); right = build(inorder[i+1..]);

🧩 Reconstruct from Preorder + Inorder Build it

Actually rebuild the tree: take roots from preorder in order, placing each via the inorder split.

💡 Intuition

Consume preorder as roots: the next value in preorder is always the next subtree's root. Use the inorder position to decide how many nodes go left vs right, then recurse. The tree materializes root-first (preorder).
🔒 Keep forever: "Pop the next preorder value as root; inorder index sizes the two subtrees."
preorder = [1,2,4,5,7,3,6] · inorder = [4,2,7,5,1,3,6]
Press play. Nodes appear in preorder as the tree builds.
🐢 🐇
🧠
Never forget: a hash map of value→inorder-index makes the split O(1), giving overall O(n).
Node build(int inLo, int inHi){
  if(inLo>inHi) return null;
  int val=preorder[preIdx++]; int i=inMap[val];
  Node n=new Node(val);
  n.left=build(inLo,i-1); n.right=build(i+1,inHi);
  return n;
}

🧩 Reconstruct from Postorder + Inorder Roots from the back

Postorder's last value is the root; consume it from the end, building right subtree first.

💡 Intuition

Read postorder backward: the last element of postorder is the root (children come before parents). Take roots from the end, and because postorder is L-R-N, build the right subtree before the left. Inorder still does the split.
🔒 Keep forever: "Postorder's last = root; consume from the back, build right before left."
postorder = [4,7,5,2,6,3,1] · inorder = [4,2,7,5,1,3,6]
Press play. Roots come from the end of postorder.
🐢 🐇
🧠
Never forget: mirror of pre+in — decrement a postIdx from the end and recurse right first, then left.
Node build(int inLo,int inHi){
  if(inLo>inHi) return null;
  int val=postorder[postIdx--]; int i=inMap[val];
  Node n=new Node(val);
  n.right=build(i+1,inHi); n.left=build(inLo,i-1);   // right first!
  return n;
}

🧩 Reconstruct a BST from Preorder Bounds trick

For a BST, preorder alone is enough — insert each value using valid value bounds.

💡 Intuition

BST order removes ambiguity: in a BST, every value has a legal range. Scan preorder; a value that fits the current bound goes as a left/right child, and you tighten the bounds as you descend. No second traversal required.
value in (lo, hi)? place it→recurse left with (lo, val)·right with (val, hi)
🔒 Keep forever: "BST preorder + value bounds uniquely rebuild the tree — one array."
preorder = [8, 5, 1, 7, 10, 12] (a BST)
Press play to rebuild the BST from its preorder.
🐢 🐇
🧠
Never forget: works because a BST's inorder is always sorted — so inorder is implied, giving you the second traversal for free.
int idx=0;
Node build(int bound){
  if(idx==n || pre[idx]>bound) return null;
  Node node=new Node(pre[idx++]);
  node.left = build(node.val); node.right = build(bound);
  return node;
}

🌿 Subtree of Another Tree Match check

Is tree T a subtree of tree S? Find a node in S where T matches exactly.

💡 Intuition

Find the matching branch: at every node of S, test whether the subtree rooted there is identical to T (same structure and values). If any node matches, T is a subtree.
for each node in S→sameTree(node, T)?→any match ⇒ yes
🔒 Keep forever: "Try to match T at every node of S; identical structure + values = subtree."
Does the subtree {2,4,5,7} appear inside the main tree? (Yes — rooted at node 2.)
Press play to search for the subtree.
🐢 🐇
🧠
Never forget: O(n·m) naive; O(n+m) via serializing both and substring search (with null markers to avoid false matches).
boolean isSub(S, T){
  if(S==null) return false;
  if(same(S,T)) return true;
  return isSub(S.left,T) || isSub(S.right,T);
}

💾 Serialize & Deserialize a Tree Preorder + null markers

Freeze & thaw: a preorder walk that writes # for null children captures the exact shape. To deserialize, read the tokens in the same preorder: a value creates a node and recurses into its two children; a # returns null.
serialize: preorder with # for null↔deserialize: rebuild in preorder

🔗 Lowest Common Ancestor I Recursive

Find the deepest node that is an ancestor of both p and q — in one clean recursion.

💡 Intuition

Where the paths meet: recurse down. If a node is p or q, report it up. If the left and right recursions both find something, this node is the split point — the LCA. Otherwise pass up whichever side found a target.
node == p or q? return it→both sides return non-null? this is LCA/else bubble up the found side
🔒 Keep forever: "If both subtrees report a target, you're the LCA; else pass up the one that did."
Find LCA(4, 7) → node 2.
Press play to find the LCA of 4 and 7.
🐢 🐇
🧠
Never forget: O(n), one pass. In a BST it's even simpler — go left/right by comparing values until p and q split.
Node lca(Node n, p, q){
  if(n==null || n==p || n==q) return n;
  Node L=lca(n.left,p,q), R=lca(n.right,p,q);
  if(L!=null && R!=null) return n;   // split point
  return L!=null? L : R;
}

🔗 Lowest Common Ancestor II Path method

Another approach: find the root-to-node path for both, then walk them together until they diverge.

💡 Intuition

Two routes to a fork: record the full path from the root to p and to q. Walk both paths in step from the top; the last node they share before diverging is the LCA.
path(root→p)·path(root→q)→last common node = LCA
🔒 Keep forever: "Compare the two root-to-node paths; the last shared node is the LCA."
Paths to 7 and 6 diverge after node 1 → LCA(7, 6) = 1.
Press play. Two paths share a prefix ending at the LCA.
🐢 🐇
🧠
Never forget: O(n) time, O(n) space for the paths. The recursive method (LCA I) avoids storing paths.
path(root, p, A); path(root, q, B);
int i=0; while(i<A.size() && i<B.size() && A[i]==B[i]) i++;
return A[i-1];   // last common node

📐 Distance Between Two Nodes Via LCA

The number of edges between p and q = depth(p) + depth(q) − 2·depth(LCA).

💡 Intuition

Up to the fork, then down: the shortest path between two nodes goes up from each to their lowest common ancestor, then the two half-paths join. So the distance is each node's depth minus twice the LCA's depth (the shared climb is counted once).
find LCA→dist = d(p) + d(q) − 2·d(LCA)
🔒 Keep forever: "distance = depth(p) + depth(q) − 2·depth(LCA)."
Distance(4, 7): LCA = 2 → path 4–2–5–7 = 3 edges.

🧠
Never forget: one LCA + three depths gives the answer. All three come from a single DFS if you're careful.
Node a = lca(root, p, q);
int dist = depth(a,p) + depth(a,q);   // from LCA down to each
