🔁 Basics of Recursion base + recursive case

A recursive function calls itself on a smaller input until it hits a base case. Every recursion needs a base case (to stop) and a recursive case (that shrinks the problem).

💡 Intuition

Descend then ascend: factorial(n) = n · factorial(n−1), with factorial(0) = 1. Calls dive down to the base case, then results multiply back up as the stack unwinds. 4! → 1 → 2 → 6 → 24.
base case stops recursion→recursive case shrinks input→results combine on return

Never forget: forget the base case → infinite recursion → stack overflow. The base case is not optional.

📏 Single Branch Recursion linear / one call

When each call makes exactly one recursive call, the recursion is linear — a straight chain of depth n, like a loop written recursively.

💡 Intuition

One path down, one path up: sum(n) = n + sum(n−1) has a single branch — no tree, just a chain. n frames deep, O(n) time and O(n) stack. sum(5) → 15.
one recursive call per frame→depth n chain→O(n) time & space
🔒 Keep forever: "Single-branch recursion is a loop in disguise — a linear chain of n frames."

Never forget: single-branch recursions convert cleanly to iteration — no stack needed, giving O(1) space.

🌳 Recursion Tree Diagram branching calls

When a call makes multiple recursive calls, the calls form a tree. The tree shows the total work and reveals repeated subproblems.

💡 Intuition

Two branches per node: fib(n) = fib(n−1) + fib(n−2) branches into a tree. Drawing it shows the exponential blow-up (and that fib(2) is recomputed — the reason to memoize). fib(4) = 3.
each call → 2 children→tree of calls→repeated subtrees = waste

📚 Recursion Stack Diagram frames push/pop

At runtime, active calls live on the call stack. Each call pushes a frame; each return pops one. The max stack height is the recursion depth.

💡 Intuition

Only one path is "live": even for a branching recursion, the stack holds just the current root-to-node path — not the whole tree. Frames push going down and pop on return. For fib(4), the stack never exceeds depth 4.
call → push frame→return → pop frame→max height = depth
🔒 Keep forever: "Space of recursion = max stack depth (one active path), not the total number of calls."

🧠
Never forget: time = total calls (tree size); space = max depth (tree height). They can differ hugely (fib: O(2ⁿ) time, O(n) space).

🔗 Pass by Reference (Backtracking) shared buffer

Backtracking reuses one shared array (passed by reference) across all calls — you must undo your choice after recursing, or later calls see stale state.

💡 Intuition

Add, recurse, remove: push a choice onto the shared path, recurse, then pop it to restore state for the next branch. Because the array is shared (by reference), forgetting the pop corrupts every sibling call. Generating subsets of {1,2} → 4 subsets.
path.push(choice)→recurse→path.pop() to undo

🧭 Distinct Paths I (Pure Recursion) right / down

Count paths from the top-left to bottom-right of a grid, moving only right or down. Recursively: paths(i,j) = paths(down) + paths(right).

💡 Intuition

Split by the first move: from each cell you either go down or right, so paths(i,j) = paths(i+1,j) + paths(i,j+1), with 1 path once you reach the destination. A 3×3 grid → 6 paths. (Pure recursion recomputes cells — fixed next.)
reach target → 1·else down + right
🔒 Keep forever: "Grid paths = sum of the two sub-paths (down + right); base case is reaching the goal."

🐢 🐇
🧠
Never forget: pure recursion here is exponential because the same (i,j) is recomputed on many branches.

🗺️ Distinct Paths II (Memoized / DP) O(n·m)

Cache each cell's answer (or fill a DP grid): dp[i][j] = dp[i−1][j] + dp[i][j−1]. Each cell is computed once.

💡 Intuition

Fill the grid: the first row and column are all 1 (only one way along an edge). Every other cell sums the cell above and the cell to its left. The bottom-right holds the answer. 3×3 grid → 6 paths, in O(n·m).
edges = 1→dp[i][j]=dp[i−1][j]+dp[i][j−1]→bottom-right = answer
🔒 Keep forever: "Memoize / tabulate the grid: each cell = above + left; the corner is the path count."

🐢 🐇
🧠
Never forget: the closed form is C(m+n−2, n−1) — but the DP grid generalizes to obstacles & weights.

☎️ Letter Combinations of a Phone Number backtracking

Each digit maps to letters (2→abc, 3→def…). Generate every combination by branching on each digit's letters.

💡 Intuition

One level per digit: at digit index i, try each of its letters, append it, and recurse to the next digit. Leaves at depth = number of digits are the answers. "23" → a/b/c then d/e/f → 9 combinations.
for each letter of digit i→append & recurse to i+1→index == len → record

💾 Letter Combinations — Saving Space in-place buffer

Instead of creating a new string at each call, mutate one shared character buffer: set the letter at the current index, recurse, then move on — O(depth) extra space.

💡 Intuition

Reuse one buffer: keep a char array of length = #digits. At index i, write each letter into buf[i] and recurse to i+1. No new strings per branch — only one buffer of size L. Same 9 combos, less allocation.
buf[i] = letter→recurse i+1→i == L → snapshot buf

🎛️ All Subsets of a Set include / exclude

For each element, decide to include it or not. n elements → 2ⁿ subsets, generated by a binary decision tree.

💡 Intuition

Two choices per element: at element i, branch into "exclude" and "include", then recurse to i+1. Each root-to-leaf path is one subset. {1,2,3} → 2³ = 8 subsets.
exclude element i·include element i→leaf = one subset

🔢 Subsets with Bitmasking iterative 2ⁿ

No recursion needed: loop a mask from 0 to 2ⁿ−1. Each bit set means "include that element" — every mask is a unique subset.

💡 Intuition

Bits are choices: for mask 0..2ⁿ−1, include element j iff bit j is set. Mask 000 = {}, 101 = {1,3}, 111 = {1,2,3}. All 2ⁿ masks give all 8 subsets — with zero recursion.
for mask = 0 … 2ⁿ−1→bit j set? include element j
🔒 Keep forever: "Bitmask subsets: iterate all 2ⁿ masks; each set bit picks an element. No recursion."

✂️ Divide and Conquer split · solve · combine

Break a problem into independent halves, solve each recursively, then combine. Here: the maximum of an array.

💡 Intuition

Halve, recurse, merge: split the array in two, find each half's max recursively (base case = single element), then combine with max(leftMax, rightMax). [3,1,4,1,5] → 5. The same skeleton is merge sort & quicksort.
divide into halves→conquer each recursively→combine results
🔒 Keep forever: "Divide & conquer = split into independent subproblems, solve, then merge the answers."

🐢 🐇
🧠
Never forget: D&C recurrences follow the Master Theorem — merge sort's T(n)=2T(n/2)+n gives O(n log n).

⚡ Fast Exponentiation O(log n)

Compute xⁿ in O(log n) by squaring: xⁿ = (x^(n/2))² for even n, and x·x^(n−1) for odd n.

💡 Intuition

Halve the exponent: instead of n multiplications, halve the exponent each step. x^10 = (x^5)², x^5 = x·(x^2)², and so on. Only ~log₂ n multiplications. 2¹⁰ = 1024.
n even → (x^(n/2))²·n odd → x · x^(n−1)·n = 0 → 1
🔒 Keep forever: "Fast power: square the half-power (even) or multiply by x (odd) → O(log n) multiplications."
Press play to compute 2¹⁰ by fast exponentiation.
🐢 🐇
🧠
Never forget: the iterative "binary exponentiation" reads the exponent's bits — same O(log n), and standard for modular power.

🧬 Balanced Parentheses constrained backtracking

Generate all valid strings of n pairs. Add '(' while opens remain; add ')' only while it wouldn't exceed the opens placed.

💡 Intuition

Prune the invalid: track open and close counts. You may add '(' if open < n, and ')' if close < open. These two rules guarantee balance and cut off dead branches early. n=3 → 5 valid strings (Catalan C₃).
open < n → add '('·close < open → add ')'→length 2n → record

🔤 Lexicographic Subsets ordered generation

Generate subsets in lexicographic order: for a start index, take the current prefix, then extend with each later element in increasing order.

💡 Intuition

Prefix then extend upward: record the current subset, then loop j from the current index to n−1, include element j, recurse from j+1, and remove it. Choosing elements in increasing index order yields lexicographic output. {1,2,3} → 8 subsets in order.
record current subset→for j = start … n−1: include, recurse(j+1), undo

🎯 Subset Sum I (Exists?) include / exclude

Does any subset add up to a target? Branch on each element (include or exclude) and check if the remaining target hits 0.

💡 Intuition

Take it or leave it: at element i, either subtract it from the target (include) or skip it (exclude). Success when target reaches 0; failure when you run out of elements. {3,34,4,12,5,2}, target 9 → true (4 + 5).
target == 0 → true·include a[i] (target−a[i])·or exclude a[i]
🔒 Keep forever: "Subset sum = include/exclude search; hit 0 → yes. Memoize (target, i) to make it pseudo-polynomial."

🐢 🐇
🧠
Never forget: pruning helps — if the target goes negative or the remaining sum is too small, cut the branch.

🧮 Subset Sum II (Count / List All) enumerate solutions

Instead of just "exists", count (or list) every subset that reaches the target — don't stop at the first hit.

💡 Intuition

Keep searching after a hit: explore the full include/exclude tree; each time the running sum equals the target, record that subset (a copy of the shared path) and continue. {1,2,3,4,5}, target 5 → 3 subsets: {5}, {1,4}, {2,3}.
sum == target → record & keep going·explore include/exclude fully
