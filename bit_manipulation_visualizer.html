🔣 Bitwise Operators I — AND · OR · XOR Foundation

The three core gates, applied bit-by-bit between two numbers.

💡 Intuition

Three voting rules per column: AND = 1 only if both bits are 1 (strict). OR = 1 if either is 1 (generous). XOR = 1 if the bits differ (the disagreement detector). Every column decides independently.
AND: both 1·OR: at least one 1·XOR: exactly one 1
🔒 Keep forever: "AND intersects, OR unions, XOR flags differences."
a = 12 (00001100), b = 10 (00001010).
Press play to compute AND, OR, then XOR bit by bit.
🐢 🐇
🧠
Never forget: AND(12,10)=8, OR=14, XOR=6. XOR is self-inverse: x^x=0, x^0=x — the key to half these problems.
a & b   // AND — keep bits set in both
a | b   // OR  — set bits in either
a ^ b   // XOR — set bits that differ
~a      // NOT — flip every bit

↔️ Bitwise Operators II — Shifts & Masks Move & edit

Shifting multiplies/divides by powers of two; masks let you get, set, clear, or toggle any single bit.

💡 Intuition

Sliding an abacus: x << k slides bits left → multiply by 2ᵏ. x >> k slides right → divide by 2ᵏ. To touch one bit, build a mask 1<<i and OR (set), AND-NOT (clear), or XOR (toggle) with it.
x<<1 = ×2·x>>1 = ÷2·set: x | (1<<i)·toggle: x ^ (1<<i)
🔒 Keep forever: "Shift to scale by powers of two; mask with 1<<i to edit one bit."
Starting x = 6 (00000110). Watch shift and set-a-bit.
Press play to shift left, shift right, and set a bit.
🐢 🐇
🧠
Never forget: get bit i → (x>>i)&1; set → x|(1<<i); clear → x&~(1<<i); toggle → x^(1<<i).
x << 1;          // 6 → 12  (×2)
x >> 1;          // 6 → 3   (÷2)
x | (1 << 5);    // set bit 5
x & ~(1 << i);   // clear bit i

🛠️ Using Bitwise Operators (Tricks) Toolbox

Three everyday one-liners: odd/even, power-of-two test, and isolating the lowest set bit.

💡 Intuition

Reading the rightmost bits: the last bit alone tells odd/even. A power of two has exactly one set bit, so x & (x−1) wipes it to 0. And x & −x magically isolates just the lowest set bit (thanks to two's complement).
odd? x&1·pow2? x&(x−1)==0·lowest bit: x&−x
🔒 Keep forever: "x&1 = parity · x&(x−1) clears lowest bit · x&−x isolates it."
Press play: parity → power-of-two → lowest set bit.
🐢 🐇
🧠
Never forget: XOR-swap a^=b; b^=a; a^=b; swaps without a temp. x&(x-1) also removes the lowest set bit (used to count bits below).
boolean odd  = (x & 1) == 1;
boolean pow2 = x > 0 && (x & (x - 1)) == 0;
int lowestBit = x & -x;   // isolates rightmost 1

🔢 Count of Set Bits (Kernighan) O(set bits)

Count the 1-bits by repeatedly stripping off the lowest set bit.

💡 Intuition

Snuffing out candles: x & (x−1) extinguishes exactly the lowest lit candle each round. Count the rounds until the number is dark (0). You only loop once per set bit — faster than checking all 32.
while x≠0→x &= x−1 (kill lowest 1)→count++
🔒 Keep forever: "x & (x−1) drops the lowest 1 — count the drops."
x = 13 (00001101) → 3 set bits.
Press play to strip the lowest 1 each step.
🐢 🐇
🧠
Never forget: loops exactly (number of set bits) times, not 32. Also known as popcount / Integer.bitCount.
int count = 0;
while (x != 0) { x &= (x - 1); count++; }
return count;

🔗 Cumulative Bitwise AND Bits only drop

AND across many numbers keeps a bit set only if every number has it — bits can only turn off.

💡 Intuition

Unanimous jury: a bit survives only if all numbers vote 1 for it. The instant one number has a 0 in that column, the bit is gone forever. So the running AND only loses bits — never gains them.
🔒 Keep forever: "AND is monotonic downward — one 0 in a column kills that bit for good."
Array [15, 14, 12, 8] → cumulative AND = 8.
Press play. Bits fall away as zeros appear.
🐢 🐇
🧠
Never forget: AND of a range [m..n] = common binary prefix of m and n (shift both right until equal, then shift back).
int result = a[0];
for (int i=1; i<n; i++) result &= a[i]; // bits only drop

🎯 Detecting the Odd One Out XOR magic

Every element appears twice except one — XOR them all and the pairs cancel, leaving the loner.

💡 Intuition

Cancelling twins: since x ^ x = 0, every duplicated pair XORs down to zero. XOR the whole array and all the twins vanish, leaving only the single unmatched number.
acc = 0→acc ^= each element→pairs cancel → loner remains
🔒 Keep forever: "XOR everything; identical pairs self-destruct; the unique survives."
Array [4, 2, 7, 2, 4] → single = 7.
Press play. Running XOR cancels the pairs.
🐢 🐇
🧠
Never forget: O(n) time, O(1) space, no sorting. XOR's cancellation is the trick behind missing-number and swapped-value puzzles too.
int acc = 0;
for (int x : a) acc ^= x;  // pairs vanish
return acc;                // the unique element

📏 Hamming Distance XOR + popcount

Count the positions where two numbers' bits differ — just popcount of their XOR.

💡 Intuition

Spot the differences: XOR lights up exactly the columns where the two numbers disagree. Count those lit bits and you have the Hamming distance — how many single-bit flips turn one number into the other.
d = a ^ b→count set bits of d
🔒 Keep forever: "Differences = XOR; distance = popcount(a ^ b)."
a = 9 (1001), b = 14 (1110) → distance 3.
Press play. XOR flags differing bits, then count them.
🐢 🐇
🧠
Never forget: total Hamming distance over an array = for each bit, (count of 1s) × (count of 0s), summed over bits.
int hamming(int a, int b) {
  int d = a ^ b, count = 0;
  while (d != 0) { d &= d - 1; count++; }
  return count;
}

🪟 Bitwise OR of Subarrays Monotonic OR

As a subarray grows, its OR only gains bits — collect all distinct OR values.

💡 Intuition

A one-way ratchet: extend a subarray to the right and OR the new element in — bits can only switch on, never off. So from any start there are at most ~30 distinct OR values (one per new bit). That bounds the whole distinct-OR set.
fix start i→extend right, OR in→collect distinct results
🔒 Keep forever: "OR only turns bits on — few distinct values, easy to enumerate."
Array [1, 2, 4] → distinct subarray ORs.
Press play. Each subarray's OR only adds bits.
🐢 🐇
🧠
Never forget: the "OR is monotonic" insight caps distinct ORs at O(n · bits) — the basis of efficient subarray-OR problems.
Set<Integer> distinct = new HashSet<>();
for (int i=0; i<n; i++) {
  int cur = 0;
  for (int j=i; j<n; j++) { cur |= a[j]; distinct.add(cur); }
}

🔽 Finding Minimum XOR (Pair) Sort + adjacent

The pair with the smallest XOR is always adjacent after sorting — so just compare neighbors.

💡 Intuition

Closest neighbours share bits: numbers that are numerically close share the most high bits, so their XOR is tiny. Sort the array, then the minimum XOR hides between some adjacent pair — check just n−1 pairs instead of all n².
sort→xor each adjacent pair→track the minimum
🔒 Keep forever: "Sort first — the minimum XOR pair is always neighbours."
Array [3, 10, 5, 25, 2, 8] → minimum XOR = 1 (from 2, 3).
Press play. Sort, then compare adjacent XORs.
🐢 🐇
🧠
Never forget: sorting gives O(n log n); a binary Trie of bits gives O(n·32) and also solves "max XOR" queries.
sort(a);
int best = MAX;
for (int i=1; i<n; i++) best = min(best, a[i] ^ a[i-1]);

📊 Multiple XOR Queries (Prefix XOR) O(1) per query

Precompute prefix XORs so any range XOR is answered instantly, like prefix sums.

💡 Intuition

XOR odometer: record the running XOR at every index. The XOR of a range [l..r] is prefix[r] ^ prefix[l−1] — the shared front part cancels itself out (because x^x=0), leaving exactly the middle stretch.
prefix[i] = prefix[i−1] ^ a[i]→query(l,r) = prefix[r] ^ prefix[l−1]
🔒 Keep forever: "Prefix XOR + cancellation = range XOR in O(1)."
Array [3, 8, 2, 6, 4], query XOR of range [1..3].
Press play. Build prefix XOR, then answer [1..3].
🐢 🐇
🧠
Never forget: use prefix[-1]=0 so queries starting at index 0 work: query(0,r)=prefix[r].
prefix[0] = a[0];
for (int i=1; i<n; i++) prefix[i] = prefix[i-1] ^ a[i];
// XOR of [l..r]:
return (l==0) ? prefix[r] : prefix[r] ^ prefix[l-1];

👥 Pair with Given XOR Hashing

Find two numbers whose XOR equals K — for each x, its partner is x ^ K.

💡 Intuition

The XOR key fits one lock: if a ^ b = K then b = a ^ K — each number has exactly one partner. Walk the array asking "has my partner x ^ K already appeared?" using a hash set.
for each x→partner = x ^ K→seen partner? pair!/else add x
🔒 Keep forever: "b = a ^ K — hash what you've seen and ask for the partner."
Array [1, 5, 3, 7, 2], K = 6.
seen:
Press play to find a pair with XOR 6.
🐢 🐇
🧠
Never forget: same shape as two-sum, but the partner is x ^ K instead of K − x. O(n) time.
Set<Integer> seen = new HashSet<>();
for (int x : a) {
  if (seen.contains(x ^ K)) return {x ^ K, x};
  seen.add(x);
}

✌️ Find Two Unique Elements XOR + partition

Every number appears twice except two singles — separate them with a differing bit.

💡 Intuition

Split the crowd by one trait: XOR everything → you get x ^ y (the two loners combined; all pairs cancelled). Pick any set bit of that result — the two loners differ there. Split all numbers into "has that bit / doesn't", and XOR each group: the twins cancel within their group, revealing x and y.
XOR all = x^y→pick a set bit→partition by that bit→XOR each group
🔒 Keep forever: "XOR all, find a differing bit, split into two groups, XOR each → the two singles."
Array [2, 4, 7, 9, 2, 4] → the two uniques are 7 and 9.
Press play. XOR all, pick a bit, split, XOR groups.
🐢 🐇
🧠
Never forget: use the lowest set bit d & -d to partition — it's guaranteed to differ between the two answers.
int xorAll = 0; for (int v : a) xorAll ^= v;  // = x ^ y
int bit = xorAll & -xorAll;                     // a differing bit
int x = 0, y = 0;
for (int v : a) if ((v & bit) != 0) x ^= v; else y ^= v;
return {x, y};
