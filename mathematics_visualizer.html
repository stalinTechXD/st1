🔗 Greatest Common Divisor Euclidean algorithm

The largest number dividing both a and b. Euclid: repeatedly replace the pair with (b, a mod b) until the remainder is 0.

💡 Intuition

Shrink by remainders: gcd(a, b) = gcd(b, a mod b), and gcd(a, 0) = a. Each step the numbers shrink fast (like Fibonacci), so it's O(log min(a,b)). gcd(48, 18): 48 mod 18 = 12 → 18 mod 12 = 6 → 12 mod 6 = 0 → 6.
gcd(a,b)=gcd(b, a mod b)→stop when b = 0→answer = a

Never forget: the subtraction form gcd(a,b)=gcd(a−b,b) also works but is slower; the modulo form is the fast one.

🧮 More on GCD (of an Array) fold the GCD

GCD is associative, so the GCD of a whole array is found by folding: gcd of the running result with each next element.

💡 Intuition

Accumulate pairwise: gcd(a,b,c) = gcd(gcd(a,b), c). Start with the first element and repeatedly combine. If the running GCD ever hits 1, you can stop early. [24, 36, 48] → gcd(24,36)=12 → gcd(12,48)=12.
g = a[0]→g = gcd(g, a[i])→final g = array GCD

♾️ Lowest Common Multiple via GCD

The smallest number divisible by both a and b. Compute it from the GCD: lcm(a,b) = a·b / gcd(a,b).

💡 Intuition

Product minus the overlap: a·b double-counts the shared factors (the GCD), so divide them out once. To avoid overflow, compute a / gcd(a,b) · b. lcm(4, 6) = 4·6 / gcd(4,6)=2 = 12.
g = gcd(a,b)→lcm = a / g · b
🔒 Keep forever: "lcm(a,b) = a·b / gcd(a,b); divide before multiplying to prevent overflow."
Press play to compute lcm(4, 6).
🐢 🐇
🧠
Never forget: for a·b to be exact, gcd must divide it — which it always does, so integer division is safe.

🧩 Generating All Factors O(√n) pairing

Divisors come in pairs (i, n/i). Iterate i only up to √n and collect both members of each pair.

💡 Intuition

Pair up around the square root: if i divides n, so does n/i. So checking i from 1 to √n finds every factor. Add both i and n/i (once if they're equal). n = 36 → {1,2,3,4,6,9,12,18,36} = 9 factors.
for i = 1 … √n→n % i == 0? add i and n/i

🚪 The Open/Close (Doors) Problem divisor parity

100 doors, pass k toggles every k-th door. Which stay open? A door ends open iff it was toggled an odd number of times — iff it's a perfect square.

💡 Intuition

Toggled once per divisor: door d is flipped on pass k exactly when k divides d. So it ends open iff d has an odd number of divisors — which happens only for perfect squares. For 10 doors → open = {1, 4, 9} = 3.
pass k toggles multiples of k→open ⇔ odd # divisors→⇔ perfect square

✅ Primality Test trial up to √n

A number is prime if no integer from 2 to √n divides it. Checking beyond √n is redundant (factors pair up).

💡 Intuition

A factor above √n implies one below: if n = a·b with a ≤ b, then a ≤ √n. So testing divisors up to √n catches any factor. 29: test 2,3,5 (√29 ≈ 5.4) — none divide → prime.
for i = 2 … √n→n % i == 0? composite→none → prime

🧠
Never forget: handle n < 2 (not prime) and 2 (prime) as edge cases; you can also skip even divisors after checking 2.

📋 Primality Test in a Range test each

To list primes up to N, run the √n primality test on every number. Simple, though a sieve is faster.

💡 Intuition

Brute but clear: for each candidate 2..N, do trial division to √candidate. Total cost ≈ O(N·√N). Great for understanding; use a sieve when N is large. Primes ≤ 20 → 2,3,5,7,11,13,17,19 (8).

🧹 Sieve of Eratosthenes O(n log log n)

Cross out multiples of each prime. Whatever survives is prime. The classic way to list all primes up to N.

💡 Intuition

Strike the composites: start with 2 — mark 4,6,8,… as composite. Move to the next unmarked number (3) and mark its multiples, and so on up to √N. Everything left standing is prime. Primes ≤ 30 → 10 primes.
for p = 2 … √N→if p unmarked, mark p·p, p·p+p, …→survivors = primes
🔒 Keep forever: "Sieve: for each prime p, cross out multiples from p·p upward — survivors are prime."

🧠
Never forget: start marking from p·p (smaller multiples already got crossed by smaller primes) — that's the efficiency trick.

🌿 Prime Factorization trial division

Break n into its prime factors by repeatedly dividing out the smallest prime that fits.

💡 Intuition

Peel off small primes: while d·d ≤ n, divide out d as many times as possible, then increment d. Any leftover > 1 is a prime factor itself. 60 = 2·2·3·5 = 2²·3·5.
for d = 2 while d·d ≤ n→divide out all d's→leftover > 1 is prime
🔒 Keep forever: "Factorize by dividing out primes up to √n; any remainder > 1 is a final prime factor."

Never forget: once you divide out a prime fully, n shrinks — so √n shrinks too, making later checks cheaper.

⚡ Fast Factorization (Smallest Prime Factor) O(log n) per query

Precompute the smallest prime factor (SPF) of every number with a sieve; then factorize any number by repeatedly jumping to its SPF.

💡 Intuition

Sieve once, factor instantly: a modified sieve stores spf[x] = the smallest prime dividing x. To factorize n, divide by spf[n], then by spf[n/spf[n]], and so on — each step removes a prime in O(1). 60 → spf 2, 2, 3, 5 = 2²·3·5.
precompute spf[] via sieve→n /= spf[n], repeat→O(log n) per factorization

🔢 Counting Divisors Faster exponent product

From the prime factorization, the divisor count is the product of (each exponent + 1) — no need to list divisors.

💡 Intuition

Pick an exponent per prime: if n = p₁^e₁ · p₂^e₂ · …, a divisor chooses each prime's power from 0..eᵢ — that's (eᵢ+1) choices each, multiplied. 60 = 2²·3¹·5¹ → (2+1)(1+1)(1+1) = 12 divisors.
factorize n→∏ (exponent + 1)→= divisor count

📐 Segmented Sieve primes in [L, R]

Find primes in a high range [L, R] without sieving from 0. Use base primes up to √R to mark composites in just that window.

💡 Intuition

Only the window matters: any composite in [L, R] has a prime factor ≤ √R. So sieve base primes up to √R, then for each base prime mark its multiples that fall inside [L, R]. Memory is O(R−L), not O(R). Range [10, 20] → 11, 13, 17, 19.
base primes ≤ √R→mark their multiples in [L,R]→survivors = primes

🎯 Implementing the Segmented Sieve offset marking

The key implementation detail: for each base prime p, find the first multiple of p that is ≥ L, then step by p through the local array.

💡 Intuition

Start at the right offset: the first multiple of p in the segment is ceil(L/p)·p (but at least p²). Map it to the local index start − L and mark every p-th cell. Range [20, 30] → primes 23, 29.
start = max(p·p, ⌈L/p⌉·p)→mark start, start+p, … ≤ R→local index = value − L

🕐 Fundamentals of Modular Arithmetic clock math

Arithmetic that wraps around a modulus m. The mod distributes over +, −, and ×, letting you keep numbers small.

💡 Intuition

Reduce as you go: (a + b) mod m = ((a mod m) + (b mod m)) mod m, and the same for multiplication. So you never let intermediate values explode. (17 + 25) mod 7: 42 mod 7 = 0 = (3 + 4) mod 7 = 0.
(a+b)%m = (a%m + b%m)%m·(a·b)%m = (a%m · b%m)%m
🔒 Keep forever: "Mod distributes over +, −, ×; reduce every step to avoid overflow (subtraction needs a +m fix)."
Press play to verify modular addition & multiplication.
🐢 🐇
🧠
Never forget: after subtraction, add m before taking mod: ((a−b)%m + m)%m — otherwise you can get a negative result.

👯 Counting Pairs frequency → C(f,2)

Count unordered pairs (i<j) of equal elements. For a value appearing f times, it forms f·(f−1)/2 pairs.

💡 Intuition

Choose 2 from each group: count frequencies, then for each value with count f add C(f,2) = f(f−1)/2. [1,2,1,3,1] → value 1 appears 3× → C(3,2) = 3 pairs.
count frequencies→Σ C(f, 2)→= pair count

🎲 Basics of Combinatorics factorial & rules

Two rules power counting: the multiplication principle (independent choices multiply) and factorials for arrangements.

💡 Intuition

Multiply the choices: arranging n distinct items = n × (n−1) × … × 1 = n! — n choices for the first slot, n−1 for the next, and so on. 4! = 4·3·2·1 = 24 arrangements.
multiplication principle→n! arrangements→building block for nPr, nCr

🔀 Permutations & Combinations order matters?

Permutations count ordered selections: P(n,r)=n!/(n−r)!. Combinations ignore order: C(n,r)=n!/(r!(n−r)!).

💡 Intuition

Divide out the ordering: P(n,r) picks r items in order. Since each group of r can be arranged r! ways, dividing by r! gives the unordered count C(n,r). n=5, r=2 → P = 20, C = 20/2! = 10.
P(n,r) = n!/(n−r)!→÷ r!→C(n,r)
🔒 Keep forever: "Permutations count order; divide by r! to get combinations (order-blind)."

🐢 🐇
🧠
Never forget: "arrangement/order/rank" → permutations; "selection/group/team" → combinations.

🧊 Understanding nCr Pascal's identity

C(n,r) counts r-subsets of n items. Its recurrence: fix one item — either include it (C(n−1,r−1)) or exclude it (C(n−1,r)).

💡 Intuition

Include or exclude: C(n,r) = C(n−1,r−1) + C(n−1,r). Every r-subset either contains a chosen element (then pick r−1 from the rest) or doesn't (pick r from the rest). C(5,2) = C(4,1) + C(4,2) = 4 + 6 = 10.
include item → C(n−1,r−1)+exclude item → C(n−1,r)
🔒 Keep forever: "C(n,r) = C(n−1,r−1) + C(n−1,r) — the include/exclude recurrence behind Pascal's triangle."
Press play to expand C(5,2) via Pascal's identity.
🐢 🐇
🧠
Never forget: symmetry C(n,r) = C(n,n−r) — choosing r to keep is the same as choosing n−r to drop.

🔻 Pascal's Triangle for nCr DP table

Build every C(n,r) at once: each entry is the sum of the two directly above it. Row n, position r gives C(n,r).

💡 Intuition

Sum the two parents: the edges are all 1 (C(n,0)=C(n,n)=1); every interior entry = left-parent + right-parent (Pascal's identity). Read C(5,2) off row 5 → 10.
edges = 1→interior = sum of two above→row n = all C(n, ·)

🐱 Introduction to Catalan Numbers 1,1,2,5,14,…

A famous counting sequence. Cₙ = Σ Cᵢ·Cₙ₋₁₋ᵢ (or C(2n,n)/(n+1)) — it appears everywhere in "balanced" structures.

💡 Intuition

Split at the matching partner: Cₙ = C₀Cₙ₋₁ + C₁Cₙ₋₂ + … + Cₙ₋₁C₀. Each term splits a structure into a left part of size i and a right part of size n−1−i. C₀=1, then 1, 2, 5, 14, 42, …
C₀ = 1→Cₙ = Σ Cᵢ·Cₙ₋₁₋ᵢ→1,1,2,5,14,…
