🕸️ What is a Graph? nodes + edges

A graph is a set of vertices (nodes) connected by edges (relationships). Unlike a tree, it can have cycles, many links, and no fixed root.

💡 Intuition

A map of connections: think cities joined by roads, or people joined by friendships. Each dot is a vertex; each line is an edge. That's it — the most general "things + relationships" structure in all of CS.
vertex = a thing→edge = a relationship→graph = V + E
🔒 Keep forever: "A graph is just dots (vertices) and lines (edges) — trees & lists are special cases of it."

🐢 🐇
🧠
Never forget: a tree is a connected graph with no cycles and exactly V−1 edges. Every tree is a graph; not every graph is a tree.

📖 Important Terms vocabulary

Vertex, edge, adjacent, path, cycle, connected — the words you'll use in every graph problem.

💡 Intuition

Speak graph: two vertices joined by an edge are adjacent (neighbors). A path is a trail of edges from one vertex to another. A cycle is a path that returns to its start. A graph is connected if every vertex is reachable from every other.
adjacent = share an edge·path = trail of edges·cycle = path back to start
🔒 Keep forever: "Adjacent = neighbors; path = a walk; cycle = a loop; connected = all reachable."
Press play to highlight a vertex, an edge, a path, and a cycle.
🐢 🐇
🧠
Never forget: directed edges are one-way arrows; weighted edges carry a cost. Plain edges (here) are undirected & unweighted.

🎯 Degree of a Node handshake

The degree of a vertex is how many edges touch it — i.e. its number of neighbors.

💡 Intuition

Count the lines: vertex 1 has edges to 0, 2, and 3 → degree 3. Sum every vertex's degree and you always get twice the edge count (each edge is counted from both ends) — the Handshaking Lemma.
degree(v) = #edges at v→Σ degrees = 2·E
🔒 Keep forever: "Degree = neighbor count; the sum of all degrees is always 2 × (number of edges)."
Press play to count degree of node 1 and verify the handshake sum.
🐢 🐇
🧠
Never forget: in a directed graph each vertex has an in-degree and an out-degree instead of one degree.

🗂️ Graph Representation list vs matrix

Two standard ways to store a graph: an adjacency list (each vertex keeps its neighbors) or an adjacency matrix (a V×V grid of 0/1).

💡 Intuition

List vs grid: the adjacency list is compact for sparse graphs (O(V+E) memory) and lists neighbors directly. The adjacency matrix answers "is u–v an edge?" in O(1) but uses O(V²) memory. Most algorithms use the list.
list: O(V+E) mem, iterate neighbors fast·matrix: O(V²) mem, edge-lookup O(1)
🔒 Keep forever: "Sparse graph → adjacency list. Need instant edge lookups / dense graph → adjacency matrix."

🧠
Never forget: undirected edges appear twice in the list and make the matrix symmetric (M[u][v]=M[v][u]).

🌊 Breadth First Search queue · layers

BFS explores level by level using a queue: visit a vertex, enqueue all unvisited neighbors, repeat. It spreads out like a ripple.

💡 Intuition

Ripple outward: start at 0, visit its neighbors (level 1), then their neighbors (level 2)… A queue (FIFO) guarantees you finish a whole level before the next. A visited set stops re-visits.
enqueue start→pop, visit, enqueue new neighbors→repeat till queue empty
🔒 Keep forever: "BFS = a queue + a visited set → explores in expanding rings from the source."
Press play for BFS from vertex 0.
🐢 🐇
🧠
Never forget: mark a vertex visited when you enqueue it (not when you pop) so it's never added twice.
q=[start]; visited={start};
while(q){ u=q.shift(); visit(u);
  for(v : adj[u]) if(!visited[v]){ visited.add(v); q.push(v); } }

🌲 BFS Tree tree vs cross edges

The edges BFS actually uses to first reach each vertex form a BFS tree. The leftover edges are cross edges.

💡 Intuition

Keep the discovery edges: whenever BFS reaches a new vertex, the edge it came through is a tree edge (green). Edges connecting already-seen vertices are cross edges (pink dashes). The tree edges span all vertices with no cycles.
first time reached → tree edge·already visited → cross edge
🔒 Keep forever: "BFS tree = the edges that first discovered each vertex; everything else is a cross edge."
Press play to split edges into tree (green) & cross (pink).
🐢 🐇
🧠
Never forget: in an undirected graph BFS produces only tree edges & cross edges — never "back edges" that skip levels.

🛣️ Shortest Path (Unweighted) BFS = shortest

On an unweighted graph, BFS finds the shortest path automatically: the level a vertex is found on = its distance from the source.

💡 Intuition

Levels are distances: because BFS finishes each ring before the next, the first time you reach a vertex is via a shortest route. Store a parent pointer as you go, then walk parents back from the target to rebuild the path. Here: 0 → 5.
BFS with dist[] & parent[]→dist[target] = hops→follow parents back
🔒 Keep forever: "Unweighted shortest path = plain BFS; record parents to reconstruct the actual route."
Press play to BFS distances then trace the 0→5 shortest path.
🐢 🐇
🧠
Never forget: BFS = shortest path only when every edge has the same weight. Weighted graphs need Dijkstra / 0-1 BFS.

♞ Knight's Minimum Moves BFS on a board

The chessboard is a hidden graph: each square is a vertex, and a knight's L-move is an edge. BFS finds the fewest moves between two squares.

💡 Intuition

Board = graph: from a square, a knight can reach up to 8 others (its L-moves = neighbors). BFS from the start square colors squares by move-count; the first time it reaches the target is the minimum number of jumps. Here (0,0) → (4,4).
square = vertex·L-move = edge→BFS layers = move count
🔒 Keep forever: "Any 'minimum moves on a grid' problem is BFS — the grid is just an implicit graph."
Press play for knight BFS from (0,0) to (4,4).
🐢 🐇
🧠
Never forget: only the move rule changes between grid-BFS problems — knight jumps vs 4-directional steps. The BFS skeleton is identical.

📏 Distance to Closest Zero multi-source BFS

For each cell in a 0/1 matrix, find its distance to the nearest 0. Seed BFS from all zeros at once.

💡 Intuition

Start everywhere at once: push every 0 into the queue with distance 0. BFS outward simultaneously — the first wave to reach a 1 gives its shortest distance to any zero. One pass, no per-cell search.
enqueue all zeros (dist 0)→BFS outward→first arrival = nearest 0
🔒 Keep forever: "Nearest-source problems = multi-source BFS: seed the queue with every source at once."
Press play for multi-source BFS from every zero.
🐢 🐇
🧠
Never forget: multi-source BFS is just BFS with many starting points — it's why it beats running single BFS per cell.

🍊 Rotten Oranges BFS in time

Rot spreads to 4-adjacent fresh oranges each minute. How many minutes until none are fresh? Multi-source BFS where each level = one minute.

💡 Intuition

Each BFS level = one minute: seed the queue with all initially rotten oranges. Every BFS ring rots the neighboring fresh ones — the number of rings is the answer. If a fresh orange is never reached, it's impossible (−1). Grid: 2=rotten, 1=fresh, 0=empty.
enqueue all rotten→each level rots neighbors→levels = minutes
🔒 Keep forever: "Rotten oranges = timed multi-source BFS — count the number of expansion waves."
Press play to spread the rot minute by minute.
🐢 🐇
🧠
Never forget: process the queue one full level at a time (record queue size) so each wave counts as exactly one minute.

🪜 Word Ladder BFS over words

Transform one word into another by changing a single letter at a time (each step must be a real word). Shortest chain = BFS.

💡 Intuition

Words are vertices: two words are adjacent if they differ by one letter. BFS from the start word spreads level by level; the level the end word appears on is the shortest transformation length. hit → hot → dot → dog → cog.
word = vertex·1-letter change = edge→BFS levels = ladder length
🔒 Keep forever: "Word ladder = BFS on a graph where edges are single-letter changes."
Press play for BFS from hit to cog.
🐢 🐇
🧠
Never forget: to find neighbors fast, try every letter a–z at each position (26·L candidates) instead of comparing all word pairs.

🔀 Word Ladder — Bidirectional BFS meet in the middle

Search from both ends at once. When the two frontiers meet, you've found the shortest ladder — while exploring far fewer words.

💡 Intuition

Two waves collide: a normal BFS frontier grows like bᵈ. Running one wave from hit (blue) and one from cog (pink) and stopping when they touch turns bᵈ into ~2·b^(d/2) — dramatically fewer nodes. Always expand the smaller frontier next.
frontier from start·frontier from end→stop when they intersect
🔒 Keep forever: "Bidirectional BFS meets in the middle — same answer, exponentially fewer nodes explored."
Press play for two frontiers meeting in the middle.
🐢 🐇
🧠
Never forget: bidirectional search needs a known target and reversible edges — perfect for word ladders & puzzles.

🧭 Depth First Search stack · recursion

DFS plunges as deep as possible along one branch before backtracking — the opposite of BFS's cautious rings.

💡 Intuition

Dive then backtrack: from a vertex, recurse into the first unvisited neighbor, and keep diving until stuck; then back up and try the next branch. Uses the call stack (or an explicit stack). Order here: 0,1,2,4,3,5.
visit u, mark it→recurse into each unvisited neighbor→backtrack when stuck
🔒 Keep forever: "DFS = go deep first (stack/recursion); BFS = go wide first (queue)."
Press play for DFS from vertex 0.
🐢 🐇
🧠
Never forget: DFS powers cycle detection, topological sort, connected components & flood fill — all "explore fully then backtrack" tasks.
dfs(u){ visited[u]=true; visit(u);
  for(v : adj[u]) if(!visited[v]) dfs(v); }

🧩 Connected Components count clusters

A component is a maximal set of mutually reachable vertices. Count them by starting a fresh traversal from each still-unvisited vertex.

💡 Intuition

Flood each island of nodes: loop over all vertices; when you hit one that's unvisited, that's a new component — run BFS/DFS to flood everything reachable, then continue. The number of times you start a flood = the component count. Here 3.
for each vertex→unvisited? count++ & flood it→total floods = components
🔒 Keep forever: "Components = number of separate BFS/DFS floods needed to cover every vertex."
Press play to color each connected component.
🐢 🐇
🧠
Never forget: Union-Find (DSU) counts components too — merge each edge's endpoints, then count distinct roots.

🏝️ Number of Islands grid flood fill

Count clusters of 1s ("land") in a grid where cells connect 4-directionally — connected components on an implicit grid graph.

💡 Intuition

Sink each island once: scan the grid; when you meet an unvisited land cell, that's a new island — flood-fill (BFS/DFS) all connected land so it's never recounted. Increment the island counter each time you start a flood. Here 2 islands.
scan cells→unvisited land? island++ & flood→count = islands
🔒 Keep forever: "Number of islands = connected-components count on a grid — flood-fill each new land cell."
Press play to flood-fill and count the islands.
🐢 🐇
🧠
Never forget: the same flood-fill pattern solves max-island-area, surrounded-regions & coloring — just change what you track.

🧱 Capture Surrounded Regions border flood

Flip every region of Os fully surrounded by Xs. A region survives only if it touches the border.

💡 Intuition

Rescue from the edges: instead of testing each region for "surrounded", flood-fill from every O on the border and mark those safe. Any O left unmarked is trapped → flip it to X.
flood O's touching the border → safe→remaining O's → flip to X
🔒 Keep forever: "Don't test 'is it surrounded' — flood from the border to find what's safe; flip the rest."

Never forget: "reach from the boundary" is the key trick — it turns a hard global test into one flood fill.

🎨 Check Bipartite Graph 2-coloring

A graph is bipartite if you can 2-color it so no edge joins same-colored vertices. BFS/DFS colors greedily; a conflict means "not bipartite".

💡 Intuition

Alternate the paint: color the start A, all its neighbors B, their neighbors A… If you ever try to color a vertex the same as an adjacent one, an odd cycle exists → not bipartite. Here the coloring succeeds: two clean teams.
BFS, color = opposite of parent→same-color edge? conflict·no conflict → bipartite
🔒 Keep forever: "Bipartite ⇔ 2-colorable ⇔ no odd cycle — check by alternating colors during BFS."
Press play to 2-color the graph.
🐢 🐇
🧠
Never forget: bipartite graphs model matchings, scheduling & "us vs them" — and only odd cycles can break 2-colorability.

🔁 Detect Cycle — Undirected parent check

DFS/BFS the graph; if you reach an already-visited vertex that isn't the one you came from, you've found a cycle.

💡 Intuition

Bumped into an old friend: during DFS, seeing a visited neighbor is fine if it's your parent (the edge you just used). But a visited neighbor that isn't your parent means there's another way back → a cycle.
DFS carrying parent→visited neighbor ≠ parent → cycle
🔒 Keep forever: "Undirected cycle = a visited neighbor that isn't your parent."
Press play to DFS and catch the back edge.
🐢 🐇
🧠
Never forget: Union-Find also detects undirected cycles — if an edge's endpoints already share a root, adding it makes a cycle.

🔃 Detect Cycle — Directed recursion stack

In a digraph, a cycle exists iff DFS finds a back edge — an edge to a vertex still on the current recursion stack (colored gray).

💡 Intuition

Three colors: white = unvisited, gray = in progress (on the stack), black = fully done. If DFS reaches a gray vertex, that edge loops back into the active path → a directed cycle.
enter → gray→edge to gray? cycle·leave → black
🔒 Keep forever: "Directed cycle = a DFS edge into a gray (on-stack) vertex."
Press play to color-DFS and find the back edge.
🐢 🐇
🧠
Never forget: "visited" alone is not enough for digraphs — you need the on-stack (gray) distinction.

📚 Topological Sort DFS finish order

Linearly order a DAG so every edge points forward. DFS and push each vertex when it finishes; reverse that list.

💡 Intuition

Finish deepest first: a vertex is only "done" after all its descendants are. So the DFS finish order, reversed, guarantees prerequisites come before dependents. Only works on a DAG (no cycles).
DFS each vertex→push on finish→reverse = topo order
🔒 Keep forever: "Topological order = reverse of DFS finish times (DAG only)."
Press play to DFS and read off the topological order.
🐢 🐇
🧠
Never forget: topo sort powers build systems, task scheduling & dependency resolution — anything with "do X before Y".

🎓 Course Schedule can finish?

Given courses with prerequisites, can you finish them all? Yes iff the prerequisite digraph has no cycle — a topological order exists.

💡 Intuition

Prerequisites are edges: course a → b means "a before b". If you can topologically order all courses (Kahn's: repeatedly take a course with no remaining prerequisites), you can finish them. A leftover cycle = impossible.
build prereq DAG→peel zero-indegree courses→all peeled? finishable
🔒 Keep forever: "Course Schedule = cycle detection: finishable ⇔ prerequisite graph is a DAG."
Press play to peel courses in a valid order.
🐢 🐇
🧠
Never forget: "Course Schedule II" just asks for the order itself — it's the topological sort you built while peeling.

🪣 Topological Sort — Kahn's BFS indegrees

The BFS alternative to DFS topo sort: repeatedly output any vertex with indegree 0, then remove it and decrement its neighbors.

💡 Intuition

Peel the ready ones: a vertex with indegree 0 has no unmet prerequisites → safe to output now. Removing it may free others (their indegree drops to 0). Keep a queue of ready vertices. If you output all of them, it's a DAG; if some never reach 0, there's a cycle.
compute indegrees→queue indegree-0→pop, output, decrement neighbors
🔒 Keep forever: "Kahn's algorithm = BFS on indegrees — output zero-indegree vertices until none remain."
Press play for Kahn's indegree-peeling topological sort.
🐢 🐇
🧠
Never forget: Kahn's doubles as cycle detection — if fewer than V vertices get output, a cycle blocked the rest.

👽 Order of Characters (Alien Dictionary) topo on letters

Given words sorted in an unknown alphabet, recover the letter order. Each adjacent word pair reveals one ordering edge; topo-sort them.

💡 Intuition

First difference wins: compare consecutive words; the first position where they differ gives an edge c₁ → c₂ (c₁ comes before c₂). Collect all such edges into a graph over letters, then topological sort. Here wrt, wrf, er, ett, rftt ⇒ w e r t f.
compare adjacent words→first diff → letter edge→topo sort letters
🔒 Keep forever: "Alien dictionary = build letter-order edges from first differing chars, then topological sort."
Press play to derive the alien alphabet order.
🐢 🐇
🧠
Never forget: only the first differing character gives an edge; and a prefix that comes after its extension (e.g. "abc" before "ab") is invalid input.

🌿 Disjoint Set Union (DSU) find + union

A structure that tracks a partition into disjoint sets, with two operations: find (which set?) and union (merge two sets).

💡 Intuition

Everyone points to a leader: each element points to a parent; the root of the chain is the set's representative. find(x) walks up to the root. union(a,b) attaches one root under the other. Same root ⇒ same set.
parent[] pointers→find = walk to root·union = link roots
🔒 Keep forever: "DSU = a forest of parent pointers; the root is the set's ID."
Press play to union elements and follow find to the root.
🐢 🐇
🧠
Never forget: naive union can build a long chain, making find O(n). The next section fixes that.

⚡ Optimized Union rank + path compression

Two upgrades make DSU nearly O(1): union by rank (attach smaller tree under bigger) and path compression (point nodes straight at the root during find).

💡 Intuition

Keep trees flat: union by rank stops tall chains by always hanging the shorter tree under the taller root. Path compression then re-parents every node on a find directly to the root — so future finds are instant. Together: amortized α(n) (inverse-Ackermann, effectively constant).
union by rank → shallow trees·find compresses path → flat
🔒 Keep forever: "Union by rank + path compression ⇒ DSU operations are effectively O(1)."
Press play to see path compression flatten the tree.
🐢 🐇
🧠
Never forget: path compression rewrites parents during find — the query itself optimizes the structure for next time.

🌉 Minimum Spanning Tree — Kruskal sort + DSU

Connect all vertices with minimum total edge weight. Kruskal sorts edges ascending and adds each one unless it forms a cycle (checked by DSU).

💡 Intuition

Greedy cheapest-first: consider edges from lightest to heaviest. Add an edge only if its endpoints are in different sets (else it makes a cycle) — merge their sets with union. Stop at V−1 edges. Total here = 16.
sort edges by weight→add if no cycle (DSU)→V−1 edges = MST
🔒 Keep forever: "Kruskal = sort edges, add the cheapest that doesn't make a cycle, using Union-Find."
Press play to build the MST edge by edge.
🐢 🐇
🧠
Never forget: Kruskal shines on sparse graphs (sort dominates: O(E log E)); Prim suits dense graphs.

🎯 Strongly Connected Components Kosaraju

An SCC is a maximal set where every vertex can reach every other. Kosaraju finds them with two DFS passes and a graph transpose.

💡 Intuition

Two passes + flip: ① DFS the graph, pushing vertices by finish time onto a stack. ② Reverse every edge (transpose). ③ Pop vertices from the stack and DFS the transpose — each DFS tree is one SCC. Here: {0,1,2}, {3,4}, {5}.
DFS → finish-order stack→transpose edges→DFS in stack order = SCCs
🔒 Keep forever: "Kosaraju = finish-order DFS, transpose, then DFS again — each tree is an SCC."
Press play to color each strongly connected component.
🐢 🐇
🧠
Never forget: Tarjan's algorithm finds the same SCCs in a single DFS using discovery/low-link values.

✂️ Articulation Points cut vertices

A vertex whose removal splits the graph into more components. DFS with discovery & low-link times finds them in one pass.

💡 Intuition

No way around it: during DFS, each vertex gets a disc time and a low = earliest reachable ancestor via its subtree. A non-root vertex u is an articulation point if some child v has low[v] ≥ disc[u] — the subtree can't bypass u. Here: {1, 3}.
DFS disc & low→child low ≥ disc[u] → u is a cut vertex
🔒 Keep forever: "Articulation point: a child's subtree can't reach above u ⇒ removing u disconnects it."
Press play to find the cut vertices.
🐢 🐇
🧠
Never forget: the same disc/low machinery finds bridges — an edge is a bridge when low[v] > disc[u] (strict).

🌲 Prim's Algorithm I grow from a vertex

Another MST builder: grow one tree outward, always adding the cheapest edge that reaches a new vertex.

💡 Intuition

Grow one blob: start from any vertex. Keep a key = cheapest known edge to each outside vertex. Repeatedly pick the outside vertex with the smallest key, add it to the tree, and relax its neighbors' keys. This O(V²) scan version is great for dense graphs. Total = 16.
pick min-key outside vertex→add to tree→relax neighbor keys
🔒 Keep forever: "Prim grows a single tree, always absorbing the nearest outside vertex."
Press play to grow the MST from vertex 0 (key scan).
🐢 🐇
🧠
Never forget: Prim & Kruskal both give a minimum spanning tree — Prim grows one tree, Kruskal merges a forest.

🌳 Prim's Algorithm II priority queue

The same growth, but a min-heap of candidate edges replaces the O(V) scan — giving O(E log V), ideal for sparse graphs.

💡 Intuition

Let a heap pick the min: push edges crossing out of the tree into a priority queue. Pop the lightest; if it reaches a new vertex, add it and push that vertex's outgoing edges. Skip edges that lead back inside. Same MST, faster edge selection. Total = 16.
push crossing edges to heap→pop lightest to a new vertex→add & push its edges
🔒 Keep forever: "Prim II = Prim with a min-heap of frontier edges → O(E log V)."
Press play to grow the MST with a min-heap of edges.
🐢 🐇
🧠
Never forget: the heap version is what you actually code in contests — same result as Prim I, better complexity on sparse graphs.

🛰️ Dijkstra's Algorithm weighted shortest path

Shortest paths from a source on a graph with non-negative weights. A min-heap always expands the closest unfinalized vertex.

💡 Intuition

Greedy nearest-first: keep tentative distances; repeatedly finalize the unvisited vertex with the smallest distance, then relax its edges (dist[v] = min(dist[v], dist[u]+w)). Once finalized, a vertex's distance is optimal — because weights are non-negative. From 0: 0,3,1,4,7.
pick min-dist unvisited→finalize it→relax its edges
🔒 Keep forever: "Dijkstra = BFS with a min-heap by distance; finalize nearest first (needs non-negative weights)."
Press play for Dijkstra from vertex 0.
🐢 🐇
🧠
Never forget: negative edges break Dijkstra — use Bellman-Ford instead. Equal weights? plain BFS already suffices.
