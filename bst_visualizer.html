🌳 What is a BST? Ordering rule

A Binary Search Tree keeps everything sorted: for every node, left subtree < node < right subtree.

💡 Intuition

A sorted filing cabinet: smaller keys always go left, larger go right — at every node, recursively. This one rule makes search, insert, and delete all O(h), and an in-order walk spits out the values in sorted order.
left subtree < node·right subtree > node·inorder = sorted
🔒 Keep forever: "Left smaller, right larger, everywhere — so inorder is sorted."

🧠
Never forget: O(h) operations — O(log n) if balanced, O(n) if degenerate (a sorted-insert chain). Balancing (AVL/Red-Black) keeps h ≈ log n.
// BST property for every node:
all(left) < node.val < all(right)

🔍 Search in a BST O(h)

Compare with the node and go left or right — each step discards half the tree.

💡 Intuition

Binary search on a tree: at each node, if the target is smaller go left, larger go right, equal → found. The ordering guarantees you never need to look at the other side.
🔒 Keep forever: "Smaller → left, larger → right, equal → found. Half the tree gone each step."

➕ Insert into a BST Attach at leaf

Walk down as if searching; when you fall off the tree, attach the new node there.

💡 Intuition

Follow the search to a gap: the value's correct spot is exactly where a search for it would end (a null child). Walk left/right by comparison until you hit that empty slot, then hang the new leaf.
🔒 Keep forever: "Insert = search until null, then attach the new leaf there."

Press play to insert 5.
🐢 🐇
🧠
Never forget: new values always become leaves. Insert order shapes the tree — sorted input makes it degenerate.
Node insert(Node n, int x){
  if(n==null) return new Node(x);
  if(x<n.val) n.left=insert(n.left,x); else n.right=insert(n.right,x);
  return n;
}

➖ Delete from a BST Three cases

Deleting a node depends on its children — leaf, one child, or two children.

💡 Intuition

Fill the hole in order: a leaf just vanishes. A one-child node is replaced by that child. A two-child node is replaced by its inorder successor (the smallest value in its right subtree) — the only value that preserves the ordering — then that successor is removed from below.
leaf → remove·one child → replace with child·two children → successor
🔒 Keep forever: "Two children? Replace with the inorder successor (min of the right subtree)."

🐢 🐇
🧠
Never forget: the inorder successor is the leftmost node of the right subtree — it has no left child, so removing it is easy.
// two-child case:
succ = min(node.right); node.val = succ.val; node.right = delete(node.right, succ.val);

🛠️ Implementation of BST Delete All cases

The full recursive delete: find the node, then handle each of the three cases in code.

💡 Intuition

One clean recursion: recurse left/right to find the node. Once found, if it has ≤ 1 child return the other child directly; otherwise copy the successor's value in and recursively delete the successor. The return value re-links parents automatically.
🔒 Keep forever: "Return the replacement subtree up the recursion — parents relink themselves."
Delete a leaf (1), a one-child node (10), then a two-child node (6).
Press play to run all three delete cases.
🐢 🐇
🧠
Never forget: returning the (possibly new) subtree root from each recursive call is what makes the re-linking effortless.
Node delete(Node n, int x){
  if(n==null) return null;
  if(x<n.val) n.left=delete(n.left,x);
  else if(x>n.val) n.right=delete(n.right,x);
  else {
    if(n.left==null) return n.right;
    if(n.right==null) return n.left;
    Node s=min(n.right); n.val=s.val; n.right=delete(n.right,s.val);
  }
  return n;
}

🔢 Kth Smallest Node Inorder count

Inorder traversal visits values in sorted order — the k-th visited node is the k-th smallest.

💡 Intuition

Count while walking sorted: do an inorder traversal and keep a counter. When the counter reaches k, you're standing on the answer — stop early. No need to finish the whole traversal.
🔒 Keep forever: "Inorder is sorted — the k-th node you visit is the k-th smallest."

✅ Is it a BST? I — Naive O(n²)

At each node, verify the whole left subtree is smaller and the whole right subtree is larger.

💡 Intuition

Check every subtree fully: for each node, find the max of its left subtree and the min of its right subtree and confirm maxLeft < node < minRight. Correct, but scanning subtrees at every node is O(n²).
🔒 Keep forever: "maxLeft < node < minRight at every node — but recomputing min/max is O(n²)."
Press play to validate every node.
🐢 🐇
🧠
Never forget: comparing only with immediate children is a classic bug — a grandchild can still violate the property.
boolean isBST(Node n){ if(n==null) return true;
  if(max(n.left)>=n.val || min(n.right)<=n.val) return false;
  return isBST(n.left) && isBST(n.right); }

✅ Is it a BST? II — Bounds O(n)

Pass a valid (min, max) range down; each node must fit its window.

💡 Intuition

Shrinking windows: the root can be anything (−∞, +∞). Going left tightens the upper bound to the parent; going right raises the lower bound. If any node falls outside its window, it's not a BST. One pass, O(n).
node in (min, max)?→left: max = node·right: min = node
🔒 Keep forever: "Carry a (min, max) range down; every node must fit its window."
Press play. Each node checks its allowed range.
🐢 🐇
🧠
Never forget: use strict inequalities (</>) to reject duplicates, and long/±∞ bounds to avoid overflow at the extremes.
boolean valid(Node n, long min, long max){
  if(n==null) return true;
  if(n.val<=min || n.val>=max) return false;
  return valid(n.left,min,n.val) && valid(n.right,n.val,max);
}

✅ Is it a BST? III — Inorder O(n)

A tree is a BST iff its inorder traversal is strictly increasing.

💡 Intuition

Sorted or bust: since a BST's inorder is sorted, just walk inorder and compare each value to the previous one. The moment a value is ≤ its predecessor, the property breaks.
🔒 Keep forever: "Inorder must strictly increase — track prev and compare."
Inorder sequence
Press play. Inorder must keep increasing.
🐢 🐇
🧠
Never forget: you only need the previous value, not the whole list — O(1) extra space with a running prev.
prev = -∞;
inorder(n){ if(n==null) return true;
  if(!inorder(n.left)) return false;
  if(n.val<=prev) return false; prev=n.val;
  return inorder(n.right); }

⚖️ Build a Balanced BST from a Sorted Array Divide

Pick the middle element as the root — recursively — to build a perfectly height-balanced BST.

💡 Intuition

Middle first: the middle of a sorted array makes a balanced root (equal halves left and right). Recurse on the left half for the left subtree and the right half for the right — the tree comes out with minimum height.
mid → root→left half → left subtree·right half → right subtree
🔒 Keep forever: "Middle element as root, recurse on halves → balanced BST (height log n)."

Press play to build the balanced BST.
🐢 🐇
🧠
Never forget: O(n). The sorted array acts as the inorder; choosing the middle balances it — height becomes ⌈log₂(n+1)⌉.
Node build(int lo, int hi){
  if(lo>hi) return null; int mid=(lo+hi)/2;
  Node n=new Node(a[mid]);
  n.left=build(lo,mid-1); n.right=build(mid+1,hi);
  return n;
}

🌲 Largest BST in a Binary Tree Post-order info

Find the biggest subtree that happens to be a valid BST — bubble up (isBST, size, min, max).

💡 Intuition

Ask each subtree to report: post-order, every node returns whether its subtree is a BST, its size, and its min/max. A node forms a BST only if both children are BSTs and maxLeft < node < minRight. Track the largest valid size seen.
children both BST?·maxL < node < minR?→size = L+R+1

🧩 Reconstruct a BST from Preorder Bounds

A BST's preorder alone rebuilds it — each value fits a valid range as you descend.

💡 Intuition

Order removes ambiguity: scan preorder; the next value becomes a node only if it fits the current upper bound. Descending left tightens the bound to the parent; the recursion places every value in its unique legal spot — no second traversal needed.
🔒 Keep forever: "BST preorder + a running bound rebuilds the tree — inorder is implied (it's sorted)."
preorder = [8, 3, 1, 6, 10, 14]
Press play to rebuild the BST from its preorder.
🐢 🐇
🧠
Never forget: O(n) with the bound trick. Postorder or level-order of a BST also uniquely rebuild it.
int idx=0;
Node build(int bound){
  if(idx==n || pre[idx]>bound) return null;
  Node node=new Node(pre[idx++]);
  node.left=build(node.val); node.right=build(bound);
  return node;
}

▶️ BST Iterator I — Controlled Stack O(h) space

Emit inorder values on demand with next() / hasNext(), using a stack of pending nodes.

💡 Intuition

Pause the inorder walk: the constructor pushes the leftmost path. Each next() pops the top (the next smallest), then pushes the leftmost path of its right child. Only the current spine is stored → O(h) space, amortized O(1) per call.
push all lefts→next: pop & return→push lefts of its right
🔒 Keep forever: "Store only the left spine; next() pops, then pushes the right child's left spine."

Never forget: O(h) space, not O(n). Perfect when you may stop early and don't want to materialize the whole inorder.
next(){ Node n=st.pop(); for(Node c=n.right;c!=null;c=c.left) st.push(c); return n.val; }
hasNext(){ return !st.isEmpty(); }

⏩ BST Iterator II — Flattened Array O(n) space

Precompute the full inorder into an array; next() is just an index step.

💡 Intuition

Flatten once, read fast: do one inorder traversal up front into a list, then keep a pointer. Every next() is a trivial O(1) array read. Simpler code, but O(n) memory even if you stop early.
🔒 Keep forever: "Precompute inorder into an array; next() = arr[i++]. Simple, O(n) space."

👥 Pair with Given Sum in a BST Sorted 2-ptr

Two values summing to a target — walk the inorder (sorted) order from both ends.

💡 Intuition

Two iterators, opposite directions: a BST's inorder is sorted, so use a smallest-first and a largest-first iterator as two pointers. If the sum is too big, advance the high one down; too small, advance the low one up; equal → found.

🔗 Lowest Common Ancestor in a BST Value split

Use the ordering: walk down until the two targets fall on opposite sides.

💡 Intuition

Where they part ways: starting at the root, if both values are smaller go left, if both are larger go right. The first node where they split (one ≤ node ≤ other) is their lowest common ancestor. No recursion or extra storage needed.
both < node → left·both > node → right·split → LCA
🔒 Keep forever: "In a BST, the LCA is the first node where p and q fall on opposite sides."

Press play to find LCA(1, 7).
🐢 🐇
🧠
Never forget: O(h) time, O(1) space — far simpler than the general-tree LCA because values tell you the direction.
while(n!=null){
  if(p<n.val && q<n.val) n=n.left;
  else if(p>n.val && q>n.val) n=n.right;
  else return n;   // split point = LCA
}

🔧 Recover a BST I — Inorder Find swapped pair

Two nodes were swapped by mistake — the inorder reveals exactly which two, so swap them back.

💡 Intuition

Spot the dips: a correct BST's inorder is sorted. With two nodes swapped, the inorder has one or two "dips" (a value smaller than its predecessor). The first offender is the earlier dip's larger value; the second is the later dip's smaller value. Swap them and the tree is fixed.
walk inorder→find first & second out-of-order nodes→swap their values
🔒 Keep forever: "Two swapped nodes = up to two inorder dips; swap the first-high with the second-low."

Never forget: if the two swapped nodes are adjacent in inorder, there's only one dip — handle that case (second = the dip's smaller value).
inorder: if(prev!=null && prev.val>cur.val){
  if(first==null) first=prev; second=cur; }
prev=cur;
// finally: swap(first.val, second.val)

🔧 Recover a BST II — Morris O(1) Space No stack

Same detection, but traverse inorder with Morris threading — constant extra space.

💡 Intuition

Threads instead of a stack: Morris traversal temporarily links each node to its inorder predecessor, so you can walk inorder without recursion or a stack. Detect the same swapped pair on the fly, then swap back — all in O(1) extra space.
Morris inorder (O(1) space)→detect the dips→swap the two values
🔒 Keep forever: "Morris threading gives O(1)-space inorder — detect & fix the swap without a stack."

while(cur!=null){ if(cur.left==null){ check(cur); cur=cur.right; }
  else { pred=rightmost(cur.left); if(pred.right==null){ pred.right=cur; cur=cur.left; }
    else { pred.right=null; check(cur); cur=cur.right; } } }
