📊 Introduction to Range Queries Prefix sums

A range query asks something about a slice [l, r] — sum, min, max — many times. Precompute so each answer is fast.

💡 Intuition

Don't recount every time: scanning [l, r] per query is O(n) each — brutal for thousands of queries. For sums, precompute a prefix array once; then any range sum is prefix[r] − prefix[l−1] in O(1). Precompute once, answer forever.
naive: scan l..r → O(n)→build prefix[] once → O(n)→query = prefix[r]−prefix[l−1] → O(1)
🔒 Keep forever: "A range sum is the difference of two prefix sums — O(1) after an O(n) precompute."

prefix[0]=a[0]; for(i=1..n-1) prefix[i]=prefix[i-1]+a[i];
sum(l,r) = (l==0) ? prefix[r] : prefix[r]-prefix[l-1];   // O(1)

🧱 Square Root Decomposition O(√n)

Split the array into blocks of size ≈ √n. Precompute each block's answer; a query uses whole-block answers + a few edge elements.

💡 Intuition

Chunk the shelf: group the array into √n blocks and store each block's sum. A query [l, r] grabs the fully-covered blocks in O(1) each and only scans the leftover elements at the two partial ends — at most √n of them. Balance: ~√n blocks + ~√n edge elements = O(√n).
precompute block sums→full blocks: add block sum·partial ends: scan elements
🔒 Keep forever: "Whole blocks answered in O(1); only the two ragged ends are scanned → O(√n). Updates stay O(1)."

🧠
Never forget: a point update touches one element and its block sum — O(1). Optimal block size is √n (balances blocks vs edges). Also solves min/max, gcd, mode…
int B = (int)Math.sqrt(n);
for(i) block[i/B] += a[i];              // precompute
sum(l,r){ int s=0;
  while(l<=r && l%B!=0) s+=a[l++];       // left partial
  while(l+B-1<=r){ s+=block[l/B]; l+=B; }   // full blocks
  while(l<=r) s+=a[l++];                  // right partial
  return s; }

⚡ Sparse Table O(1) min / max

For idempotent operations (min, max, gcd), precompute the answer for every interval of length 2ᵏ — then any range is two overlapping blocks.

💡 Intuition

Powers-of-two shortcuts: build a table where sparse[k][i] = min over [i, i+2ᵏ−1], each row combining two cells from the row above. Since min doesn't mind overlap, any range [l, r] is covered by two blocks of length 2ᵏ (the largest power ≤ range length) — answer in O(1).
build rows k=0,1,2… (O(n log n))→k = ⌊log₂(len)⌋→min(sparse[k][l], sparse[k][r−2ᵏ+1])
🔒 Keep forever: "Two overlapping 2ᵏ blocks cover any range — O(1) min/max because overlap doesn't matter."
Array [5,2,4,7,6,3,8,1]. Range-min query [1, 6].
Press play. Build the table, then answer with two blocks.
🐢 🐇
🧠
Never forget: O(1) queries but no updates (rebuilding is O(n log n)). Overlap is only OK for idempotent ops — for sum, use two disjoint blocks or a segment tree.
// build
for(i) sparse[0][i]=a[i];
for(k=1;(1<<k)<=n;k++)
  for(i;i+(1<<k)-1<n;i++)
    sparse[k][i]=min(sparse[k-1][i], sparse[k-1][i+(1<<(k-1))]);
// query [l,r]
int k=log2(r-l+1);
return min(sparse[k][l], sparse[k][r-(1<<k)+1]);
